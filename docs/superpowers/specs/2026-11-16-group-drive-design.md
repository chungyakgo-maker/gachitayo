# 그룹 주행 (방 코드·카톡 초대·순서·차 간격·목적지 공유·모두 지도에) 설계

2026-11-16 · 사용자 요청과 시안 확인. 시안: 시작 창, 방장 대기실, 카톡 초대 카드, 참가자 목적지 받기, 그룹 주행 지도.

## 사용자 결정 (대화 그대로)

- "방코드를 카톡으로 공유하기(앱 출시하면 바로 앱으로 입장해야함)" → 초대는 **카톡 카드**(카카오 JavaScript SDK 카카오톡 공유, 디고 앱 Web 플랫폼 도메인 등록 + JavaScript 키).
  키가 없으면 폰 공유 창·링크 복사. 링크는 `https://…/gachitayo/#/join/{코드}` (앱 출시 뒤 유니버설 링크는 따로, 내 도메인 필요)
- "방에 접속하면 주행 순서 방장이 순서 바꾸기 가능" → 대기실 ↑↓
- "방장이 차들간의 거리(델타값 초 1초~)" → 차 간격 1~10초, 0.5초 단위, 모두 같은 값
- "입장 한 사람들 컬러도 모두 다르게" → 들어온 순서로 8색 중 하나 (안 겹치게)
- "방장이 목적지 설정하면 모두 같은 경로 수신" + "목적지 없어도 되지만 중간에 목적지 정하고 공유할수 있어야함"
  → 목적지 없이도 출발. 방장이 아무 때나 목적지를 정하면 방장의 경로가 모두에게 가고, 참가자는 "이 경로로 진행"을 누르면 그 경로로 안내
- "모두 지도에 표시" → 주행 지도에 모두 색 번호 점 + 이름

제 결정 (사용자에게 알림): 한 방 8명, 차 간격 1~10초, "앞 차" = 순서상 바로 앞 사람(1번은 앞 차 없음), 경로를 벗어나면 자기 위치에서 같은 목적지로 다시 찾기.

## 구조

- D1 `rooms(id, code, host_id, created_at)`: 6자리 코드 → 방. 코드는 24시간 동안만 유효, 그 안에서는 겹치지 않게
- Durable Object `GroupRoom` (방마다 하나, SQLite 저장): 참가자(계정·닉네임·색·순서·방장), 차 간격, 목적지(이름·위경도), 경로(점들)와 경로 판.
  실시간 위치는 웹소켓으로 받아 다른 참가자에게 그대로 전한다(저장하지 않음, 마지막 하나만 메모리)
- API
  - `POST /api/rooms` → `{roomId, code}` (만든 사람이 방장·1번)
  - `POST /api/rooms/join {code}` → `{roomId}` (가득 차면 409 "방이 가득 찼어요", 없거나 지난 코드면 404 "방을 찾지 못했어요")
  - `GET /api/rooms/{id}` → 방 상태 (참가자만)
  - `POST /api/rooms/{id}/order {userIds}` · `/gap {gapS}` · `/dest {name, lat, lon, route:{points,distanceM,durationS}}` (방장만) · `/leave`
  - `GET /api/rooms/{id}/route` → 경로 점들 (참가자만)
  - 웹소켓 `/group/{id}` (열쇠는 Sec-WebSocket-Protocol, 앞 친구 간격과 같은 방식): 보내기 `{t, lat, lon, speed, heading}`, 받기 `{type:'pos', userId, …}` / `{type:'state', …}`
- 앱 `src/app/group.ts`: 방 상태, 연결, 내 위치 보내기(주행 중 GPS 1초에 1번), 방장 동작, 참가자 경로 받기.
  주행 화면은 다른 사람들을 색 번호 점으로, 칸 1은 앞 차와의 간격(앞 친구 간격 계산 그대로, 목표 = 방 차 간격), 그 아래 순서 줄.
  목적지가 있으면 경로 안내(커브 표지판 포함)를 그 경로로

## 하지 않을 것

방 채팅, 강퇴, 방장 넘기기, 주행 기록 함께 보기, 앱 유니버설 링크(출시 때).
