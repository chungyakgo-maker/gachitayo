# 목적지로 주행 (카카오 길찾기 경로 + 커브 표지판) 설계

2026-11-16 · 사용자 승인: "카카오로 경로검색 및 설정후 표지판 주행 ㄱ" (목적지 고르기는 "지도 찍기 + 코스 목록")

## 1. 왜

커브 표지판(사양서 8.4)은 코스 선에서만 계산된다. 그래서 미리 달려 코스로 만들지 않은 길(처음 가는 길)에서는 표지판이 뜨지 않는다.
사용자 요청: "내 초행경로도 표지판이 뜨게 … 내비 경로처럼 최종목적지를 찍고 가면 더 편할거같긴한데", "경로 이탈하면 새경로 받아오는것도 되냐".

성공: 목적지를 지도에서 찍거나 코스 목록에서 고르면 카카오 길찾기 경로가 나온다. 그 경로로 주행하면 처음 가는 길에서도 커브 표지판이 뜬다.
경로를 벗어나면 새 경로를 받아 표지판이 이어진다.

## 2. 목표 · 하지 않을 것 · 실패로 치는 것

목표
- 주행 시작 → "목적지로 주행" → 목적지 고르기(지도 길게 눌러 핀, 최근 목적지, 코스 출발점·도착점) → 경로 미리보기 → 출발
- 주행 중: 경로 선(주행 지도), 다음 커브 표지판·화면 색(코스 주행과 같은 칸·같은 그림), 목적지까지 남은 거리, 이탈 시 다시 찾기, 도착 표시
- 기록 남기기 켜기/끄기 (켜면 일반 기록 주행과 같고, 끝난 뒤 지금처럼 "코스로 저장" 제안을 받는다)

하지 않을 것 (이번 범위 밖)
- 장소 이름 검색: 카카오 로컬은 디고 앱에서 막혀 있다(403 OPEN_MAP_AND_LOCAL). 켜려면 유료 월렛이 필요해 쓰지 않는다
- 음성 안내, 차로·교차로 회전 안내(턴바이턴), 경유지, 교통 상황에 따른 주행 중 경로 갈아타기
- 경로를 코스로 자동 저장 (기록 주행 뒤 기존 "코스로 저장" 흐름만)

실패로 치는 것
- 청약고·메리고 키나 무료 사용량을 쓰는 것, 월렛 연결을 유도하는 것
- 위치(출발·목적지 좌표)가 서버 로그나 CI 로그에 남는 것
- 코스 주행(랩·델타·코스 이탈 안내)의 동작이 바뀌는 것
- 주행 중 길찾기를 쉬지 않고 계속 부르는 것 (재탐색 간격·하루 한도)

## 3. 확인한 사실 (2026-11-16 서버 점검, 일회용 갈래 kakao-check)

- (처음 설계 · 6절에서 네이버로 바뀜) 카카오모빌리티 자동차 길찾기 `GET https://apis-navi.kakaomobility.com/v1/directions`, 머리 `Authorization: KakaoAK {디고 REST 키}` → 신청 없이 HTTP 200
- 응답: `routes[0].result_code` (0 = 길찾기 성공), `result_msg`(한국어), `summary.distance`(m)·`duration`(초),
  `sections[].roads[]`에 `name`, `distance`, `vertexes`([경도, 위도, 경도, 위도, …])
- `origin=경도,위도,angle=도` 로 진행 방향을 주면 그 방향에 맞는 경로가 나온다 (angle 90 / 270에서 서로 다른 경로)
- 오류는 HTTP 200에 result_code로: 104 "출발지와 도착지가 5 m 이내로 설정된 경우 경로를 탐색할 수 없음", 103 "도착 지점 주변의 도로를 탐색할 수 없음"
- 서울역 → 남산 6.2 km 경로가 꼭짓점 195개 (평균 32 m 간격, 굽은 곳은 촘촘)
- 카카오모빌리티는 상업 서비스면 무료 사용량 안에서도 제휴가 필요하다고 안내한다 → 출시 전 다시 확인 (대기 목록)

## 4. 접근 방법

| | 방법 | 장점 | 단점 |
|---|---|---|---|
| **A (고름)** | 일반 주행 위에 "경로 안내"를 얹는다. 경로는 코스가 아니라 따로 든 선, 따로 따라가는 계산 | 랩·코스 엔진을 건드리지 않는다. 재탐색 때 경로만 갈아 끼운다 | 경로 따라가기 계산을 하나 더 둔다 (기존 STracker 재사용으로 작게) |
| B | 경로를 임시 편도 코스로 만들어 코스 주행 | 랩 엔진·표지판을 그대로 쓴다 | 이미 출발선에 서 있어 출발선 통과를 못 잡는다. 재탐색마다 랩이 끊긴다. 코스 목록·기록이 임시 코스로 지저분해진다 |
| C | 출발 전 미리보기만 (재탐색 없음) | 가장 작다 | 사용자가 물은 "벗어나면 새 경로"가 없다 |

## 5. 설계

### 5.1 서버 `POST /api/route` (worker/src/route.ts)

- 계정 열쇠 필요 (`authenticate`). 본문 1 KB 이하: `{ from: {lat, lon}, to: {lat, lon}, headingDeg?: number }`
- 좌표 검사: 숫자, 한국 범위(위도 32~39.5, 경도 124~132.5). 아니면 400 "한국 안에서만 길찾기가 돼요"
- 하루 한도: D1 `route_usage(user_id, day, count)` (day = 한국 날짜). 부르기 전에 1 올리고 300을 넘으면 429 "오늘 길찾기를 너무 많이 했어요. 내일 다시 해 주세요"
- 카카오 호출: `origin=경도,위도[,angle=정수]&destination=경도,위도&priority=RECOMMEND`, 8초 제한. 키가 없으면 503 "길찾기를 쓸 수 없어요"
- 결과
  - 카카오 HTTP 오류·제한 시간 → 502 "길찾기 서버가 응답하지 않아요"
  - result_code ≠ 0 → 404, 메시지는 카카오 `result_msg` 그대로 (한국어)
  - 성공 → `{ distanceM, durationS, points: [[위도, 경도], …], destName }`. 꼭짓점을 이어 붙이고 바로 앞과 같은 점은 뺀다. 소수 6자리.
    `destName` = 마지막 도로 중 이름이 있는 것 (예: "남산공원길"), 없으면 null
- 좌표·응답은 로그에 남기지 않는다

### 5.2 엔진 `RouteGuide` (src/engine/route/routeGuide.ts, 순수 계산)

- 입력: 경로 위경도 점들 + 평면 원점(주행 스냅숏의 origin). 평면 꺾은선을 만들고 커브 표지판 목록(`paceNotes`)을 한 번 계산한다
- 따라가기: 기존 `STracker`를 그대로 쓴다 (코스 형식 대신 "꺾은선 + 편도"만 받게 매개변수 형식만 넓힌다). 30 m 넘게 벗어나면 경로 밖
- `update(x, y, v, t, gpsOk)` → `{ s, onRoute, lateralM, remainingM, arrived, wantReroute }`
  - `wantReroute`: GPS가 괜찮은 채로 경로에서 50 m 넘게 3초 넘게 벗어나 있음
  - `arrived`: 경로 위에서 남은 거리 30 m 이하, 또는 마지막 점까지 30 m 이하이면서 경로로도 150 m 안 (검토 반영: 헤어핀·맞은편 차로에서 일찍 도착하지 않게)
  - 아주 긴 경로는 따라가기 선을 5만 점까지만 (200 km면 4 m 간격), 지도 그리기는 카카오 점 그대로 (검토 반영)
- 수치는 `ROUTE` 상수 하나에 (offM 50, offForMs 3000, rerouteGapMs 20000, arriveM 30)

### 5.3 앱 상태 `routeNav` (src/app/routeNav.ts)

- 목적지 화면 상태: 목적지(위경도·이름·종류), 경로, 상태(idle · loading · ready · error), 오류 글, 기록 남기기(기본 켬)
- 출발 (`startRouteDrive`): 탭 처리 안에서 `beginPrepare()` → 기록 남기기면 `chooseCourse(null)`, 아니면 `chooseFreeDrive()` → 안내 켬
- 주행 중: 스냅숏(10 Hz)마다 RouteGuide를 돌린다 (원점이 바뀌면 다시 만든다). 주행 단계(`driving`)에서만
  - `wantReroute` + 받는 중 아님 + 지난 요청 뒤 20초 + 통신 있음 → 지금 위치(+ 속도 3 m/s 넘으면 진행 방향)로 새 경로. 받으면 갈아 끼운다
  - 실패하면 예전 경로를 그대로 두고 20초 뒤 다시. 요청은 10초 제한 (검토 반영)
  - 다시 찾는 중이어도 경로 위로 돌아오면 표지판을 다시 보인다 (검토 반영)
  - 이미 주행·기록 중이면 출발하지 않는다 (목적지 화면에 "진행 중인 주행이 있어요"). 준비 화면에서 코스를 고르면 안내를 끝낸다 (검토 반영)
  - 도착하면 재탐색을 멈추고 "도착했어요"
- 주행이 끝나면(단계가 idle) 안내를 지운다
- 최근 목적지: 폰에만(localStorage) 5개, 30 m 안이면 같은 곳으로 보고 앞으로 올린다

### 5.4 화면

- 주행 시작 시트: "목적지로 주행 · 지도에서 목적지를 찍으면 카카오 경로로 커브 표지판을 띄워요" → `#/destination`
- 목적지 고르기 (`DestinationScreen`, 지도 전체 + 위·아래 얹은 카드)
  - 위: 뒤로, "목적지 고르기", 안내 "지도를 길게 눌러 목적지를 찍어요"
  - 지도: 메인 지도와 같은 선 지도. 길게 누르면 핀, 경로가 오면 경로 선(하늘색)·경로에 맞춰 화면 맞추기
  - 아래 (경로 없을 때): 최근 목적지, 코스 출발점·도착점 (지금 위치에서 가까운 순, 거리 표시)
  - 아래 (경로 받는 중 / 받음 / 오류): "경로 찾는 중…" / "남산공원길 부근 · 6.2 km · 17분 · 커브 12개" + 기록 남기기 + [이 경로로 출발] / 오류 글 + [다시 시도]
  - 지도에서 찍은 곳 이름: `destName` + " 부근", 없으면 "지도에서 고른 곳"
  - 위치를 아직 모르면 경로를 부르지 않고 "위치 확인 중"
- 주행 화면 (`DriveView`에 `nav` 하나 추가)
  - 주행 지도: 경로 선을 코스 선과 같은 그림(하늘색)으로, 목적지에 도착선
  - 표지판 칸·화면 색: 코스가 없고 경로가 있으면 경로의 다음 커브. 경로 위일 때만 (벗어나면 숨김)
  - 칸 1 제목: "목적지까지 3.2 km" / 벗어남 "경로를 벗어났어요" / "새 경로 찾는 중…" / "도착했어요" (기록 안 함이면 " · 기록 안 함")
- 선 지도가 없는 폰(사진 지도)에서도 길게 누르기·경로 선이 되게 Leaflet 쪽에도 같은 기능

### 5.5 개인정보

- 경로를 찾을 때 지금 위치와 목적지가 디고 서버를 거쳐 카카오모빌리티로 간다. 서버는 저장하지 않고 하루 횟수만 센다
- 개인정보 처리방침(ios 갈래 `public/privacy.html`)에 한 줄, 사양서 변경 이력에 한 줄

## 6. 짓는 사람에게 맡기는 것

- 목적지 화면 카드 모양·글자 크기는 기존 메인 화면 카드(`card`, `sheet-item`)를 따른다
- 길게 누르기 시간 550 ms, 움직임 10 px 넘으면 취소 (제 판단)
- 테스트: Worker(카카오 가짜 응답), 엔진(직선+커브 경로), 앱(재탐색 간격·최근 목적지), 화면(시트·목적지 화면·주행 화면)

## 6. 변경 (2026-11-16): 네이버 길찾기 + 장소 검색

사용자 결정 "카카오 길찾기를 뭐하러해 그냥 네이버 쓰는김에 네이버 길찾기 쓰면 되잖아, '만항재' 검색하면 나와야 한다고".

- 길찾기: 네이버 클라우드 Maps **Directions 15** (`https://maps.apigw.ntruss.com/map-direction-15/v1/driving?start=경도,위도&goal=경도,위도`,
  머리 `X-NCP-APIGW-API-KEY-ID`·`X-NCP-APIGW-API-KEY`). 응답 `code` 0 = 성공, 아니면 `message`(한국어)를 그대로 404로.
  `route.traoptimal[0].path` = [경도, 위도] 점들, `summary.distance`(m)·`duration`(ms), `section[].name` = 도로 이름.
  출발 진행 방향 칸이 없어 다시 찾기 때 방향은 보내지 않는다(앱은 그대로 보내고 서버가 버림).
  사용자가 등록한 앱은 Directions 15 (Directions 5는 구독 안 됨, 서버 점검 결과).
- 장소 검색: 네이버 클라우드 **NAVER API HUB 지역 검색** (`https://naverapihub.apigw.ntruss.com/search/v1/local?query=…&display=5`, 같은 머리).
  `mapx`·`mapy` = WGS84 도 × 10⁷. 제목의 `<b>`·HTML 기호를 걷어 낸다. 서버 `GET /api/places?q=` → `[{name, category, address, lat, lon}]` 최대 5개.
  계정당 하루 500번 (D1 `search_usage`, 검색어는 저장하지 않음). 2026-11-16 점검: "만항재" → 만항재(고개,골짜기), 만항재(자연명소), 만항재(등산코스), 만항재쉼터, 야생화탐방로.
- 목적지 화면: 위 카드 아래에 검색창(입력칸 16px). 검색하면 아래 카드가 "검색 결과"(이름 · 분류 · 주소 · 거리), "검색 지우기"로 최근·코스 목록으로 돌아간다.
- 키: GitHub Secrets `NCP_MAP_CLIENT_ID`·`NCP_MAP_CLIENT_SECRET`(Maps), `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`(API HUB) → CI가 있는 것만 Worker 비밀값으로.
- 개인정보: 길찾기·검색 때 지금 위치·목적지·검색어가 네이버 클라우드로 간다 (ios 갈래 privacy.html).
