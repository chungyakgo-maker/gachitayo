# 바이크 모드 설계 (탈것·바이크 표시·바이크 길찾기·기울기)

2026-11-18 · 세영 "바이크 모드를 넣고 싶어, 내 위치 표시를 바이크 5종, 지도 경로 표시할 때 바이크만 다닐 수 있게" → 시안 확인 → "ㅇㅇ 크루저 ㄱㄱ 기울기 ㄱㄱ 추가해야지 바이크모드 추가하는김에 다 추가하고 이거까지해서 정식배포 심사 준비하자".

시안: `docs/mock/2026-11-18-bike-mode.jpg`(탈것·바이크 5종·바이크 길찾기, 승인), `docs/mock/2026-11-18-lean.jpg`(기울기, 세영 "바이크 그림은 빼, 깔끔한 바늘로" → "ㅇㅋ 이렇게 진행").

## 세영 결정

- 바이크 5종: 스쿠터 · R차 · 크루저 · 네이키드 · 모타드 ("할리"는 상표라 **크루저**, 세영 "크루저 ㄱㄱ")
- 길찾기는 바이크가 다닐 수 있는 길로 (이륜차는 고속도로·자동차전용도로 통행 금지, 도로교통법 63조)
- 기울기(뱅크각)도 넣는다 ("기울기 ㄱㄱ")
- 이것까지 넣고 정식 배포 심사 준비

## 1. 탈것 설정

- `settings.vehicle: 'car' | 'bike'` (기본 car), `settings.bikeMarker` 5종 (기본 R차 `sport`). 폰에 보관, 잘못된 값은 기본으로
- 설정: "탈것" (자동차 / 바이크) + 바이크면 "내 바이크 표시 (주행 지도)" 5칸, 자동차면 예전 "내 차 표시" 4칸
- 주행 준비: "탈것" 칸 (여기서도 바꿈, 바이크면 "R차 · 길찾기는 고속도로·자동차전용도로를 피해요")
- 주행 시작 때 바이크면 세션에 `vehicle: 'bike'` (이 기기에만, 요약에 최대 기울기)

## 2. 바이크 표시 (`src/ui/overlay/bikeMarks.ts`)

- 시안 SVG(64 칸, 위에서 본 바이크 + 헬멧)를 캔버스 그림 목록으로 옮김. 어두운 바탕 원(반지름 31 px) + 그림자 + 옅은 색 테 → 차 표시와 같은 크기
- 진행 방향으로 돌린다. 방향을 모르면 위를 보게(점으로 바꾸지 않음)
- `meMarker(settings)` = 바이크면 바이크 모양, 아니면 차 모양 → 주행 지도에 넘김

## 3. 바이크 길찾기 (서버 `worker/src/route.ts`, 앱 `src/app/routeNav.ts`)

- 앱: 탈것이 바이크면 `/api/route`에 `vehicle: 'bike'` (자동차는 예전과 똑같은 요청·응답)
- 서버: 네이버 Directions 15 `option=traavoidcaronly:traavoidtoll:tracomfort` (자동차 전용 도로 회피 우선 · 무료 우선 · 편한 길, 한 번 부름에 세 경로)
  - 같은 경로는 하나로, 경로의 도로 이름(section.name)에 자동차 전용 도로가 **없는 것부터** (그 안에서는 위 순서)
  - 자동차 전용 도로 알아보기: 이름에 고속도로·고속국도·고속화도로·도시고속·자동차전용·순환고속, 또는 이름 목록(올림픽대로·강변북로·내부순환로·북부/동부/서부간선도로·강남순환로·분당수서로·분당내곡로·자유로·제2자유로·신월여의지하도로·서울외곽순환도로·동서고가로·신천대로)
  - 응답에 `vehicle: 'bike'`, `warnRoads`(섞인 도로 이름), `alt`(지금 후보 번호)·`alts`(후보 수). `alt`를 보내면 그 후보
- 화면(목적지): "바이크 경로 · 고속도로·자동차전용도로 피함" 표시. 섞였으면 노란 테 알림 "경로에 자동차 전용 도로가 섞였을 수 있어요 (이름)." + "다른 길로 다시 찾기"(다음 후보, 후보가 하나면 "출발 전에 경로를 확인해 주세요")
- 경로를 벗어나 다시 찾기·팀 주행 각자 길찾기도 바이크 기준. 바이크인데 남이 준 경로가 바이크 경로가 아니면(팀 방장이 자동차, 시험판) 내 위치에서 한 번 다시 찾는다. 안내 중에 탈것을 바이크로 바꾸면(주행 준비 화면) 바이크 경로로 다시 찾는다(검토 지적). 내가 찾은 경로는 다시 묻지 않는다
- 못 막는 것: 네이버 옵션이 "회피 우선"이라 섞일 수 있고, 도로 이름 목록에 없는 자동차 전용 도로는 경고하지 못한다 → 시안에 적은 대로 "100%는 아님"
- 서버가 예전이면(배포 전) `vehicle`을 무시하고 자동차 경로를 준다. 앱은 다시 묻지 않는다(하루 한도를 태우지 않게)

## 4. 기울기 (엔진 `src/engine/derive/lean.ts`, 화면은 시안 승인 뒤)

- 바이크는 몸통째 기울어 폰 좌우 가속도가 거의 0 → G미터로는 코너가 안 보인다. 물리식 tan θ = 속도 × 도는 빠르기 ÷ 중력
- 도는 빠르기 = 융합 진행 방향(ψ)의 1.5초 최소제곱 기울기 (검토 지적: 거치 보정 전 GPS만이면 진행 방향이 1초마다 계단이라 0.5초 차이는 실제 30°가 6°~43°로 출렁였다 → 1.5초는 28.5°~31.5°, 대신 약 0.7초 늦음). 15 km/h 아래는 0, ±60°로 자름, 0.25초 평활
- 라이브: `LiveState.leanDeg`(+ 오른쪽, − 왼쪽), `maxLeanLeftDeg`·`maxLeanRightDeg`
- 요약: 처리된 궤적(10 Hz 속도·나침반 방향)으로 같은 계산 → `maxLeanOf` (예전 기록도 다시 계산됨)
- 화면(시안 `docs/mock/2026-11-18-lean.jpg`): 상단 칸 "기울기" — 반원 눈금(±60°), 바늘이 그 각도를 가리키고 큰 숫자 (세영 "바이크 그림은 빼, 깔끔한 바늘로"), 왼쪽 파랑·오른쪽 빨강, 이번 주행 최대(작은 삼각형·아래 글자). 탈것을 바이크로 바꾸면 G미터 칸 → 기울기, 자동차로 돌리면 다시 G미터. 주행 요약 "최대 기울기 (추정) 왼쪽 ○° · 오른쪽 ○°"(바이크 주행만)
- 기록 파일(CSV·GPX 내보내기)에는 넣지 않는다

## 화면 (기울기, 구현)

- 지도 모드 상단 칸 "기울기"(`src/ui/overlay/leanGauge.ts`): 실제 칸(약 174 × 100) 비율로 다시 놓음(시안 190 × 140을 그대로 줄이면 작은 글씨가 7 px)
- 대시보드 모드: 바이크면 G미터 자리에 기울기
- 주행 중 칸을 눌러 바꿀 때 기울기는 바이크에서만 순서에 들어감(상단 표시 값 화면에서는 늘 고를 수 있음)
- 앱스토어 스크린샷 7번 `docs/release/screenshots/7-바이크-기울기.jpg`

## 시험

- 설정 값·잘못된 값, 탈것 바꾸기 화면, 바이크 5종 색·크기·회전, 주행 지도에 고른 모양
- 서버: 세 옵션 한 번에, 전용 도로 없는 경로 고르기, 섞이면 이름, alt 순환, 자동차는 예전 응답 그대로, 도로 이름 알아보기
- 앱: 바이크면 vehicle 실음, 다른 후보, 자동차 경로를 받은 바이크는 내 위치에서 다시 찾기
- 기울기: 물리식, 원 돌기 수렴(왼쪽 −·오른쪽 +), 느리면 0, 60° 자르기, 처리된 궤적 최대, 엔진 최대 기억

## 배포

- 서버(바이크 길찾기)는 main 배포가 필요 → 세영에게 묻는다. 서버를 먼저 올려야 바이크 경로가 나온다
- 앱 화면은 Codemagic 빌드(정식 `ios-release`, 테스트 `ios-testflight`)
