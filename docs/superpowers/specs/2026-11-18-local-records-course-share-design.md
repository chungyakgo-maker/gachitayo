# 기록은 폰에만 · 모두의 코스 · 팀 방 코스 지정 (설계, 2026-11-18)

시안: `docs/mock/2026-11-18-local-storage.jpg`(①~⑤), `docs/mock/2026-11-18-course-share.jpg`(⑥~⑩). 정식 빌드 기준(위치 공유 끔).

## 왜

- 세영: "서버비용 때문이지. 기록 업로드 뭐하러 하는거야 기기에 저장하게 해", "동기화 기능도 없애".
  주행 기록(원본 센서 파일은 한 번에 수 MB)을 서버에 올려 두는 비용을 없앤다.
- 세영: "코스 등록 기능(사람들이 등록한 코스로 동일하게 달리는 것)", "팀 방에서 팀장이 경로 지정을 할 수 있듯이 코스 지정해서 동일한 코스로 달릴 수 있는 기능".
  코스는 작아서(줄인 선 수십 KB) 서버에 두어도 비용이 거의 없다.
- 세영: "등록 후 관리자인 내가 삭제할 수 있게", 공개 방식은 A(바로 공개 + 신고·차단).

## 목표

1. 주행 기록(세션·랩·원본·처리 결과)과 내 코스, 즐겨찾기·분류는 이 폰에만 저장한다. 업로드·동기화·로그인 때 되살리기를 없앤다.
2. 폰이 너무 커지지 않게 원본 센서 자료는 최근 30개 주행만 남기고, 내 코스는 200개까지.
3. 폰을 바꿀 때를 위해 "전체 백업 파일"을 만들고 불러온다(서버를 거치지 않음).
4. 내 코스를 "모두의 코스"로 공개하고, 다른 사람이 받아 같은 출발선·도착선으로 달린다.
5. 신고·차단·이름 거르기(애플 심사 1.2), 관리자(세영)가 앱 안에서 공개 코스를 숨기고 지운다.
6. 팀 방에서 방장이 목적지 대신 코스를 정하면 모두 같은 코스로 달린다.

## 안 하는 것

- 코스 순위표, 남의 기록·랩 시간 보기 (기록은 폰에만이라).
- 여러 기기 사이 기록 맞추기, 자동 클라우드 백업 (백업은 사람이 파일로).
- 공개 코스 승인 대기(B안), 링크로만 주고받기(C안).

## 하면 실패인 것

- 1.0.0(심사 중·출시 후)을 깨뜨리는 서버 변경. 이번 작업의 서버 변경은 **더하기만** 한다. 예전 업로드 API는 그대로 둔다.
- 1.0.1로 올리는 순간 서버에만 있던 사람의 기록이 사라지는 것 (처음 켤 때 한 번 받아 둔다).
- 정렬·목록 때문에 내 위치를 서버로 보내는 것 (가까운 순은 폰에서 정렬).
- 공개 코스에서 올린 사람의 집이 드러나는 것 (공개 창 경고, 출발·도착 주변 자르기는 안 함 — 코스 선은 그대로여야 같은 코스).

## 방법 고르기 (세영이 고름)

| 안 | 내용 | 장단점 |
|---|---|---|
| **A (고름)** | 공개하면 바로 보임. 신고 3건이면 자동 숨김, 관리자가 확인·삭제. "이 사람 코스 안 보기". 이름 나쁜 말 거름 | 운영 부담 적음, 애플 1.2 충족. 잠깐 나쁜 코스가 보일 수 있음 |
| B | 관리자 승인 뒤 공개 | 가장 안전, 올라올 때마다 세영이 확인해야 함 |
| C | 공개 목록 없이 카톡 링크로만 | 신고 불필요, 남의 코스 찾아보기 불가 |

기록 저장은 "폰에만 + 파일 백업" 한 가지(서버 보관은 비용 때문에 뺌, iCloud 자동 백업은 네이티브 작업이 커서 뺌).

## 1부: 기록은 폰에만

### 없애는 것 (앱)
- 세션·코스 업로드 대기열과 동기화(`src/app/sync.ts`, `src/sync/*`의 올리기 부분), 설정 "동기화" 칸, 메인 "업로드 대기 N건"·"계정 연결이 끊겨 업로드할 수 없어요" 알림, 요약의 "업로드됨/업로드 대기" 줄.
- 로그인 때 서버에서 되살리기(`src/app/restore.ts`의 평소 흐름, `RestoreBanner`). 아래 "옮기기" 한 번만 남긴다.
- 즐겨찾기·분류의 서버 맞추기(`/api/prefs` 읽기·쓰기). 폰(localStorage)에만.
- 원본이 정리된 기록을 서버에서 다시 받아 계산하는 길(`courses.ts` ensureRaw의 서버 부분, 원본 7일 뒤 정리 `KEEP_RAW_AFTER_UPLOAD_MS`).
- 로그인 안내 "로그인하면 폰을 바꿔도 기록이 돌아와요" → "로그인하면 친구·팀을 쓸 수 있어요 · 기록은 이 폰에만 저장돼요".

### 그대로 (서버)
로그인, 닉네임·프로필 사진, 친구, 팀·팀 방, 길찾기·장소 검색, 인기 도로(아래), 실시간 주행 신호. 서버의 예전 기록 API(`/api/sessions`, `/api/courses`, `/files/…`, `/api/prefs`)는 1.0.0 때문에 남긴다.

### 처음 켤 때 한 번 옮기기 (1.0.1)
서버 열쇠가 있는 계정(카카오·애플·로그인 없이 시작한 계정 모두 — 예전 앱은 모두 올렸다)이면 한 번:
(가) 서버에 있고 이 폰에 없는 기록은 지금의 되살리기 코드로 받아 같은 id로 다시 계산한다.
(나) 이 폰에 있지만 원본이 이미 정리된 기록(예전 앱은 올린 뒤 7일이면 폰 원본을 지웠다) 중 최근 30개는 서버에서 원본만 받아 덩어리로 되돌린다. 나머지는 `rawPruned`. 끝나면 폰에 "옮김 끝"을 기억하고 다시 하지 않는다. 실패한 것은 다음 실행 때 다시(최대 몇 번은 만드는 사람이 정함). 진행은 지금 되살리기 알림 모양을 그대로 쓴다. 서버의 기록 파일 지우기는 **이번 작업에 넣지 않는다** — 세영 허락을 받고 따로 한다.

### 기록 지우기
1.0.1에서 기록을 지우면 폰에서 지우고, 예전에 서버에 올라간 기록(`uploadedAt` 있음)이면 `DELETE /api/sessions/{id}`를 한 번 부른다(실패하면 작은 "지울 것" 목록에 남겨 다음 실행 때 다시). 1.0.0 대기열에 남아 있던 지우기도 처음 켤 때 보낸다. 그래야 "기록은 폰에만" 안내가 맞고, 옮기기가 지운 기록을 되살리지 않는다(옮기기는 지우기 목록에 있는 id를 받지 않는다). 업로드 대기열의 나머지(세션·코스 올리기)는 버린다.

### 웹
웹도 똑같이 폰(브라우저)에만. 사파리는 홈 화면에 추가하지 않은 사이트의 저장소를 오래 안 쓰면 지울 수 있어서, 웹의 저장 공간 칸에 "브라우저는 오래 안 쓰면 기록을 지울 수 있어요 · 홈 화면에 추가하거나 백업해 두세요"를 보이고 `navigator.storage.persist()`를 부탁한다.

### 원본 한도
- 원본 센서 자료(덩어리 `chunks`)는 시작 시각이 최근인 30개 기록만 남긴다. 주행이 끝나 처리된 뒤에 오래된 것부터 지운다. 기록 중·처리 전 기록은 세지 않고 지우지 않는다.
- 원본을 지운 기록은 `rawPruned: true`. 랩·요약·궤적(처리 결과)·분석·GPX/CSV 내보내기는 되고, 다시 재생·다시 계산은 안 된다. 기록 탭에 "원본 정리됨 · 분석·내보내기는 돼요, 다시 재생은 안 돼요".
- 코스 선을 고쳐 다시 계산할 때 원본 없는 기록은 지금처럼 건너뛴다(서버에서 받지 않음).
- 설정 "오래된 원본 지금 지우기": 30개 넘는 것이 없으면 꺼짐. (한도 30은 코드 한 곳의 값)

### 내 코스 한도
기본 코스를 뺀 코스(내가 만든 것 + 받은 코스) 200개. 넘으면 새로 만들기·받기·불러오기에서 "내 코스가 200개예요. 안 쓰는 코스를 지운 뒤 다시 해 주세요".

### 설정 › 저장 공간 (시안 ①)
기록 수, 원본 남은 기록 수와 대략 크기, 내 코스 N / 200, 막대(폰 저장 공간 중 디고가 쓰는 양, `navigator.storage.estimate()`; 못 얻으면 막대 없이 숫자만). 크기는 대략값이면 된다.

### 백업 파일 (시안 ②③)
- 이름 `디고 백업 YYYY-MM-DD.dgo`. 안은 ZIP(파일 하나로 공유·저장하기 쉽게): `manifest.json`(형식 판, 만든 때, 기록·코스 수), 코스·기록·처리 결과·비교 랩·즐겨찾기·분류, 원본이 있는 기록의 원본 파일(지금의 원본 파일 형식 `RawFileV1`, gzip).
- 메모리에 한꺼번에 올리지 않게 기록마다 따로 묶어 이어 붙인다(만드는 사람이 라이브러리를 정함 — 작고 의존 없는 것).
- 만들기: 지금의 `shareOrDownload`(앱은 공유 창, 웹은 내려받기). 만든 때·크기를 기억해 "마지막 백업 11월 18일 · 38 MB".
- 불러오기: 파일 고르기 → "기록 N개 · 내 코스 N개, 이미 있는 건 그대로 두고 없는 것만 더해요" → 불러오기. 같은 id는 건너뛰고, 기본 코스는 같은 기본 코스로, 같은 모양 코스(`sameCourse`)는 있는 코스로 잇는다. 원본 한도·코스 한도를 지킨다(넘는 원본은 불러온 뒤 정리).
- 기록 탭: 기록이 5개 이상이고 마지막 백업(없으면 첫 기록) 뒤 30일이 지나면 "마지막 백업이 30일 지났어요 · 백업하기"(닫으면 30일 동안 다시 안 뜸).

### 로그아웃·계정 지우기 (시안 ④)
- 로그아웃: 기록·코스는 기본으로 남긴다. "기록과 내 코스도 이 폰에서 지우기" 체크하면 지운다. "지우기 전에 백업 파일 만들기 ›". 업로드 대기·서버 연결을 기다리는 막음은 없앤다(서버 열쇠 지우기만 통신이 필요, 실패해도 폰에서는 로그아웃).
- 계정 지우기: 서버 계정과 내가 공개한 코스를 지운다. 폰 기록은 로그아웃과 같은 체크로 묻는다.

### 인기 도로
기록을 안 올리므로 새 신호: 기본 코스·모두의 코스로 주행을 끝내면 `POST /api/drove {course}` (코스 열쇠만, 위치·시간 없음, 서버가 받은 날짜만 적음, 계정·코스·날짜마다 한 줄). 인기 도로 수 = 이 표의 서로 다른 계정 수 + 예전 세션 표(서버 기록을 지우기 전까지). 실시간(`/api/driving`)은 모두의 코스 열쇠도 받게 넓힌다.

## 2부: 모두의 코스

### 코스 열쇠
받은 공개 코스는 폰의 `Course`에 `shared: {id, by}`(공개 번호, 올린 사람 닉네임). 즐겨찾기 열쇠 `s:{id}`(백업·다시 받기에도 같다). 인기·실시간 신호도 `s:{id}`, 기본 코스는 지금처럼 `b:{key}`.

### 공개하기 (시안 ⑥)
- 코스 상세(내가 만든 코스, 선이 있는 것)에 "모두에게 공개". 창: 이름·종류·길이·지역, 경고 "코스 선·이름·내 닉네임이 모두에게 보여요. 출발·도착이 집이나 회사 근처면 공개하지 마세요", "기록(랩 시간)은 올라가지 않아요", 체크 "일반 도로 법규를 지키며 달릴 수 있는 길이에요"(체크해야 공개).
- 보내는 것: 이름, 종류, 출발선·도착선, 줄인 선(1 m 간격 선을 오차 2 m 이내로 줄임. 받는 폰이 다시 1 m 간격으로 편다), 길이, 구간 경계. 서버가 출발점으로 시·도 이름을 붙인다(네이버 역지오코딩, 실패하면 빈칸). 정렬용으로 출발점 좌표를 둔다.
- 누가: 공개하기·신고는 카카오·애플로 로그인한 계정만(로그인 없이 시작한 계정은 한 사람이 여러 개 만들 수 있어 신고 3건 숨김을 악용할 수 있다). 목록 보기·받기·주행·"안 보기"는 누구나. 로그인 안 했으면 "공개하려면 카카오나 Apple로 로그인해 주세요".
- 제한: 계정당 공개 20개, 길이 300 m ~ 100 km, 이름 40자, 나쁜 말(서버·앱이 같은 목록) 거름.
- 공개한 코스 상세에는 "공개 중 · N명 받음", "공개 코스도 고친 선으로 바꾸기"(선·이름을 고쳤을 때), "공개 내리기". 이미 받은 사람 폰의 코스는 바뀌지 않는다.

### 목록·상세 (시안 ⑦⑧)
- 코스 탭 분류 칩에 "모두의 코스". 정렬 칩: 가까운 순(폰이 지금 위치로 정렬, 위치를 서버로 안 보냄; 위치 모르면 많이 받은 순)·많이 받은 순·새로 올라온 순. 줄: 작은 선 그림, 이름, 종류·길이·지역, "올린 사람 ○○ · N명 받음".
- 목록은 서버가 공개 중인 코스 요약(선 빼고, 출발점 포함)을 쪽 단위(한 쪽 300개, 다음 쪽 표시)로 준다. 폰은 모두 받아(처음엔 몇 쪽 안 됨) 잠시 기억하고 폰에서 정렬한다. 많아지면 시·도 칩을 더하는 것은 나중 일. 상세를 열 때 선을 받는다.
- 메인 지도 "코스 보기"에도 같은 칩. 지도에는 출발점 표시만(선은 상세에서).
- 상세: 지도, 정보, "이 코스로 주행"(폰에 담고 주행 준비 — 코스 상세의 그 단추와 같게), "내 코스에 담기", "출발점으로 길찾기", 아래 작게 "신고"·"이 사람 코스 안 보기". 이미 담은 코스면 "내 코스에 있어요"로 그 코스를 연다.
- 받기: `POST …/add`로 받은 수 +1(계정마다 한 번). 담은 코스는 오프라인에서도 기본 코스처럼 달린다.

### 신고·차단·관리 (애플 1.2)
- 신고 이유: 위험한 길·불법 주행 유도·이름이 불쾌함·기타(한 줄). 계정마다 한 번. 서로 다른 3명이 신고하면 바로 숨김(목록·상세에서 안 보임, 올린 사람에게는 "신고로 숨겨졌어요").
- "이 사람 코스 안 보기": 서버에 차단 목록(내 계정만 씀), 목록에서 뺀다. 설정 "안 보는 사람"에서 풀기.
- 관리자: Worker 설정값 `ADMIN_USER_IDS`(GitHub Secrets → 배포 때, 쉼표로 여러 계정). `/api/me`가 `admin: true`를 주면 설정에 "관리자 · 모두의 코스 관리". 화면: 신고·숨김 먼저, 그다음 전체(최근 순). 줄마다 보기·숨김 풀기·지우기(지우면 되돌리지 않음, 받은 사람 폰의 복사본은 남음)·"이 계정 공개 막기"(그 계정의 공개 코스를 모두 숨기고 새로 공개 못 함, 풀기 있음 — 표 `publish_bans`). 세영 계정 번호는 설정 계정 칸의 "계정 번호 복사"로 얻는다.
- 약관(`public/privacy.html` 옆 이용 규칙)에 "불쾌·위험한 코스는 지우고 올린 계정을 막을 수 있다" 한 줄. 심사 메모에 신고·차단·관리 위치를 적는다.

### 서버 (더하기만)
- D1 표: `public_courses`(번호, 올린 계정, 이름, 지역, 종류, 길이, 출발선·도착선, 구간 경계, 줄인 선, 출발점 좌표, 받은 수, 신고 수, 상태 open/hidden, 만든·고친 때), `course_reports`(코스, 계정, 이유, 때; 코스·계정 하나), `course_adds`(코스, 계정), `user_blocks`(계정, 안 볼 계정), `course_drives`(계정, 코스 열쇠, 날짜).
- API: `GET /api/shared`(요약 목록, 내 차단 반영) · `GET /api/shared/{id}`(선 포함) · `POST /api/shared`(공개) · `PUT /api/shared/{id}`(올린 사람: 선·이름 바꾸기) · `DELETE /api/shared/{id}`(올린 사람·관리자) · `POST /api/shared/{id}/add` · `POST /api/shared/{id}/report` · `GET/POST/DELETE /api/blocks…` · `GET /api/admin/shared` · `POST /api/admin/shared/{id} {hide|show}` · `POST /api/drove`.
- 계정 지우기 때 그 계정의 공개 코스·신고·받기·차단 줄을 같이 지운다.

## 3부: 팀 방 코스 지정 (시안 ⑨⑩)

- 대기실 "목적지 · 모두 같은 경로" 칸이 "이번 주행 · 방장이 정해요 [목적지 | 코스]"로. 방장이 코스를 고르는 창: 내 코스·기본 코스·즐겨찾기·모두의 코스(같은 분류 칩). 주행 중에도 바꿀 수 있는지는 목적지와 같게.
- 방 상태에 `course`(이름·종류·길이·기본 코스 열쇠 또는 공개 번호) 추가, 코스 모양(줄인 선 + 출발선·도착선)은 경로처럼 방 저장소에 따로. 목적지와 코스는 하나만(하나를 정하면 다른 하나는 비움). 판 번호(routeVersion)는 같이 올린다.
- 예전 앱(1.0.0)도 같은 방에 있을 수 있다: 서버는 코스를 정하면 `dest`를 "코스 이름 · 출발점"(출발선 위치)으로 같이 채워, 예전 앱은 출발점 목적지로 받는다.
- 팀원 창 "방장이 코스를 정했어요"(지도, 이름, 종류·길이, "받으면 내 폰에 담기고, 출발하면 지금 위치에서 출발점까지 안내해요", "이 코스로 진행"/"나중에"). 받으면: 같은 기본 코스·같은 공개 번호·같은 모양 코스가 폰에 있으면 그것, 없으면 새로 담는다(코스 한도 적용).
- 출발 준비: 그 코스를 고르고(`chooseCourse`), 내 위치에서 출발점까지 길찾기(정식은 방장 위치를 보내지 않으므로 각자 찾음). 출발선을 지나면 랩타이머·내 베스트 델타, 지금 코스 주행과 같다.
- 방장이 보내는 코스 모양은 서버가 크기(예: 100 KB 이하)·점 수를 검사한다.

## 순서·출시

1부 → 2부 → 3부 (3부의 "모두의 코스" 고르기는 2부 뒤). 각 부분 테스트(TDD), 앱·서버 테스트 통과. 1.0.0 승인 뒤 1.0.1로 한 번에. 서버 배포는 세영에게 물어보고(더하기만이라 1.0.0에 영향 없음). 개인정보 처리방침·위치 약관·앱스토어 개인정보 항목(기록은 폰에만, 공개 코스는 "사용자 콘텐츠")·심사 메모를 고친다.

## 만드는 사람에게 맡긴 것

압축 라이브러리 선택, 원본 크기 대략 계산법, 줄인 선 형식(인코딩), 옮기기 재시도 횟수, 나쁜 말 목록 내용, 관리자 화면 모양(설정 안 목록이면 됨), 서버 표 열 이름·색인.

- 원본 한도 30·코스 한도 200·공개 20개·신고 3건은 숫자 한 곳에서 바꿀 수 있게.
- 백업 알림 조건(기록 5개 이상, 30일).

- 웹도 폰에만 + 브라우저가 지울 수 있다는 안내.
