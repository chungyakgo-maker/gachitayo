# 카카오 로그인 + 새 폰에서 기록 되살리기 (설계)

작성 2026-11-13. 사용자 결정: "A ㄱㄱ" (로그인 + 계정 연결 + 새 폰에서 기록·코스 되살리기를 한 번에).

## 1. 왜 하나

- 지금 계정은 폰마다 저절로 생기는 이름 없는 계정이다. 폰 열쇠(무작위 토큰)가 그 폰의 브라우저 저장소에만 있다.
- 그래서 브라우저 데이터를 지우거나 폰을 바꾸거나, 웹앱에서 아이폰 앱 디고로 옮기면 그 계정으로 다시 들어올 수 없다.
- 디고 출시를 앞두고 "내 계정"이 필요하다. 사용자는 이미 청약고·메리고에서 카카오 로그인을 쓰고 있고, 디고용 카카오 앱을 새로 만들었다.
  - 키는 GitHub Secrets에 `KAKAO_REST_API_KEY`, `KAKAO_CLIENT_SECRET`로 넣었다.
  - 리다이렉트 URI는 `https://gachitayo-api.chungyakgo.workers.dev/auth/kakao/callback`으로 등록했다.
- 성공의 모습:
  - 카카오로 로그인한 사람이 새 폰(또는 디고 앱)에서 카카오로 로그인하면, 닉네임·친구·내 코스·주행 기록이 돌아온다.
  - 되살린 기록의 랩 시간은 예전 폰과 같다.

## 2. 목표 / 하지 않을 것 / 실패로 볼 것

**목표**
- 첫 화면에 "카카오로 시작하기"를 둔다. 기존 "닉네임만 넣고 시작"(익명)은 그대로 둔다.
- 설정에서 지금 쓰는 익명 계정을 카카오에 연결한다. 연결하면 그 계정이 그대로 카카오 계정이 된다(옮길 것 없음).
- 이미 다른 폰에서 쓰던 카카오로 로그인하면, 이 폰의 익명 계정 기록·코스·친구를 그 카카오 계정으로 합친다.
- 로그인한 폰에 없는 기록·코스는 서버에서 받아 되살린다. 원본을 받아 폰에서 다시 계산하고, 진행 상황을 보여 준다.
- 로그아웃.

**하지 않을 것 (이번 범위 밖)**
- 애플 로그인. 아이폰 앱 심사에 필요하다(App Store 심사 지침 4.8). 애플 개발자 등록 뒤 `ios` 갈래에서 한다.
- 디고 앱(Capacitor)에서의 로그인 창 처리. `ios` 갈래를 합칠 때 같이 한다. 아래 흐름은 앱에서도 그대로 쓸 수 있게 만든다.
- 계정 삭제 때 카카오 연결 끊기. 계정 삭제는 `ios` 갈래에만 있으므로 합칠 때 붙인다(카카오 Admin 키 필요, 그때 사용자에게 요청).
- 이메일·전화번호·프로필 사진 받기. 카카오 회원번호와 닉네임만 받는다.
- 한 계정에 카카오 여러 개 연결, 계정끼리 나누기.

**실패로 볼 것 (돌아가도 실패)**
- 남의 기록(위치 기록)을 볼 수 있게 되는 모든 경우. 위치는 민감 정보다.
- 로그인하다가 이 폰의 기록이 사라지는 것.
- 기존 익명 사용자가 아무것도 안 했는데 로그아웃되거나 "계정 끊김"이 뜨는 것.
- 운영 중인 다른 서비스(Supabase 두 프로젝트, 청약고·메리고 Cloudflare, 청약고·메리고 카카오 앱)를 건드리는 것.

## 3. 제약

- 서버는 기존 Cloudflare Worker `gachitayo-api` + D1 `gachitayo` + R2 `gachitayo-sessions`만 쓴다. gachitayo로 시작하는 자원만 만든다.
- 비밀값은 GitHub Secrets → CI가 Worker 비밀값으로 넣는다. 저장소는 공개라 로그에 값·사용자 위치를 찍지 않는다.
- 화면 글은 한국어. 시안(스크린샷)을 보여 주고 승인받은 뒤 배포한다.
- Worker 무료 요청당 외부 호출 50개 제한. 콜백은 카카오 호출 2번이면 된다.
- 테스트 먼저(TDD). 모든 결정은 사양서(`docs/specs/2026-11-12-gachitayo-phase1-spec.md`) 변경 이력에 한 줄씩 남긴다.

## 4. 만드는 방법 (고려한 것과 고른 것)

**로그인 처리 위치**
- **고름: 서버(Worker)가 카카오와 직접 주고받기 (REST 방식).**
  - 앱은 카카오 로그인 화면만 연다. 비밀값과 카카오 토큰은 서버에만 있다.
  - 앱은 일회용 코드로 우리 폰 열쇠를 받는다.
  - 웹앱·홈 화면 앱·디고 앱 모두 같은 흐름이다.
- 버림: 카카오 JavaScript SDK를 웹에 넣기. 디고 앱(capacitor://)에서 그대로 쓸 수 없고, 결국 서버 확인이 필요하다.
- 버림: Firebase 등 로그인 대행. 카카오가 기본 제공이 아니라 유료 설정이 필요하다. Supabase는 운영 중이라 금지다.

**되살리기**
- **고름: 서버의 원본 파일(.raw.json.gz)을 받아 폰에서 다시 계산.**
  - 이미 있는 "PC에서 기록 가져오기"(`importRawFile`)와 같은 길이라 랩이 같게 나온다.
  - 받는 양이 많아 기록이 많으면 몇 분 걸린다.
- 버림: 처리된 결과만 받기. 빠르지만 폰 저장 구조를 새로 만들어야 해서 틀릴 곳이 늘어난다.

**홈 화면 앱(아이폰) 대비**
- 애플은 "홈 화면 웹앱에서 다른 도메인 OAuth도 앱 안에서 열린다"고 하지만, 다른 저장소의 창에서 끝난다는 보고도 있다(확인 안 됨).
- 그래서 돌아온 곳에 이 로그인을 시작한 증거(아래 verifier)가 없으면, 6자리 번호를 보여 주고 앱에 입력하게 하는 길을 같이 만든다.

**버린 위험한 방법: 앱이 서버에 "끝났나?"를 계속 묻기(폴링)**
- 공격자가 자기가 시작한 로그인 링크를 피해자에게 보낸다고 하자.
- 이미 디고에 동의한 피해자는 동의 화면 없이 바로 넘어가고, 공격자 쪽 앱이 피해자 계정의 열쇠를 받게 된다.
- 그래서 결과는 "로그인을 끝낸 그 창"에만 넘기고, 시작한 쪽만 아는 verifier를 같이 요구한다.

## 5. 설계

### 5.1 서버 표 (D1 마이그레이션 `0003_identities.sql`)

- `identities (provider TEXT, subject TEXT, user_id TEXT REFERENCES users(id) ON DELETE CASCADE, created_at TEXT)`
  - 기본 키 `(provider, subject)`, 고유 `(user_id, provider)`.
  - provider는 지금 `'kakao'`만 쓴다(나중에 `'apple'`). subject는 카카오 회원번호 문자열.
- `user_tokens (token_hash TEXT PRIMARY KEY, user_id TEXT REFERENCES users(id) ON DELETE CASCADE, created_at TEXT)`
  - 로그인으로 받은 기기별 폰 열쇠. 한 계정에 여러 폰이 동시에 들어올 수 있게 한다.
  - 기존 `users.token_hash`(첫 익명 열쇠)는 그대로 둔다.
- `oauth_states (state TEXT PRIMARY KEY, verifier_hash TEXT, user_id TEXT NULL, return_to TEXT, created_at INTEGER, result_user_id TEXT NULL, result_kind TEXT NULL, code_hash TEXT NULL, code_tries INTEGER DEFAULT 0, done_at INTEGER NULL)`
  - 로그인 한 번의 상태. 10분 지나면 지운다(시작할 때마다 오래된 행 정리).

`authenticate()`는 `users.token_hash` 또는 `user_tokens.token_hash`에서 사용자를 찾는다.

### 5.2 흐름

1. **시작** `POST /auth/kakao/start {returnTo, verifierHash}`
   - 폰 열쇠(Authorization)는 있으면 보낸다.
   - 앱이 무작위 verifier를 만들어 폰에 두고, 그 SHA-256만 보낸다.
   - 서버 처리:
     - `returnTo`의 출처가 `ALLOWED_ORIGIN`인지 확인한다(나중에 디고 앱 출처 추가).
     - 열쇠가 있으면 그 사용자를 `user_id`로 적는다.
     - 무작위 state 행을 만들고 `{url}`(카카오 인가 주소)을 돌려준다.
   - 카카오 인가 주소: `kauth.kakao.com/oauth/authorize?client_id=…&redirect_uri=<Worker>/auth/kakao/callback&response_type=code&state=…`
   - 남용 방지: 같은 IP에서 1시간에 시작 30번.
   - 카카오 비밀값이 없으면 503을 돌려준다.
   - 앱은 `location.href = url`로 이동한다.
2. **콜백** `GET /auth/kakao/callback?code&state` (카카오가 브라우저를 보냄)
   - state 행을 확인한다(있고, 10분 안, 아직 안 끝남).
   - 카카오 토큰 교환(`kauth.kakao.com/oauth/token`, client_secret 포함) → `kapi.kakao.com/v2/user/me`로 회원번호·닉네임을 받는다. 카카오 토큰은 저장하지 않는다.
   - 카카오 회원번호와 닉네임만 state 행에 적는다. **계정은 여기서 바꾸지 않는다.**
     - 연결·새로 만들기·합치기는 마치기에서 verifier와 코드를 확인한 뒤에 한다(검토 지적).
     - 그래야 공격자가 자기가 시작한 링크를 피해자에게 보내도, 피해자 계정에 공격자 열쇠가 붙지 않는다.
   - 6자리 숫자 코드와 긴 일회용 코드를 만들어 해시로 저장한다.
   - `returnTo#/auth/kakao?state=…&code=<긴 코드>`로 보낸다(302).
   - 사용자가 취소하거나 카카오 오류면 `#/auth/kakao?state=…&error=cancelled|failed`로 보낸다.
3. **마치기** `POST /auth/kakao/finish {state, verifier, code}`
   - `code`는 URL로 받은 긴 코드, 또는 사용자가 입력한 6자리 숫자다.
   - verifier의 해시와 코드가 맞는지 확인한다.
   - 시작할 때 사용자 B가 적혀 있으면, 마치기 요청의 폰 열쇠도 B의 것이어야 한다.
   - 그다음 5.3 규칙(연결·새로 만들기·합치기)을 D1 batch 한 번으로 적용한다.
   - 새 폰 열쇠를 만들어 `user_tokens`에 넣고 `{userId, token, nickname, kind}`를 돌려준다.
   - state 행은 지운다. 한 번만 쓸 수 있다.
   - 6자리 숫자는 5번 틀리면 그 로그인은 끝난다.
   - 요청에 이전 폰 열쇠가 있으면 그 열쇠는 지운다(로그아웃 처리).
4. **돌아온 창에 verifier가 없을 때** (홈 화면 앱이 다른 창에서 끝난 경우)
   - 그 창은 "디고 앱으로 돌아가서 이 번호를 입력하세요: 482913 (다른 사람에게 알려 주지 마세요)"를 보여 준다.
   - 원래 앱은 로그인이 진행 중인 동안 번호 입력 칸을 보여 준다.

### 5.3 연결·새로 만들기·합치기 규칙 (마치기에서, verifier·코드 확인 뒤)

카카오 회원번호 K, 시작할 때의 사용자 B(없을 수 있음):

| K 연결 상태 | B | 결과 (`kind`) |
|---|---|---|
| 없음 | 없음 | 새 계정을 만든다. 닉네임은 카카오 닉네임(앞뒤 공백 빼고 20자, 비면 "드라이버"). 가입 제한(같은 IP 1시간 10개)을 같이 쓴다. → `created` |
| 없음 | 익명 | K를 B에 연결 → `linked` |
| 없음 | 이미 다른 카카오 | 새 계정 → `created` (화면에서 막히는 경우라 드묾) |
| A에 연결 | 없음 / B = A | A → `login` |
| A에 연결 | 익명 B ≠ A | B를 A로 합친다(5.4) → `merged` |
| A에 연결 | 다른 카카오 계정 B | 합치지 않고 A → `switched` (화면에서 막히는 경우라 드묾) |

### 5.4 합치기 (B → A, D1 batch 한 번 = 한 덩어리로)

- `courses`, `sessions`, `laps`의 owner_id를 B에서 A로 바꾼다.
- 친구:
  - B의 친구 관계를 양쪽 방향 모두 A로 옮긴다(`INSERT OR IGNORE`).
  - A와 자기 자신 관계는 빼고, B 관계는 지운다.
- B의 `presence`를 지운다.
- `users` B 행을 지운다(B의 열쇠도 같이 없어진다). 이 폰은 마치기 응답으로 받은 A의 새 열쇠를 쓴다.
  - 앱은 마치기가 진행되는 동안 업로드·확인을 멈춘다.
  - 그 사이 받은 401은 "계정 끊김"으로 처리하지 않는다.
- 파일은 R2에서 옮기지 않는다(무료 호출 수 제한). 대신:
  - 파일 게이트웨이 GET/HEAD `/files/A/{sid}...`에 그 키가 없으면, `sessions` 행(id = sid, owner = A)의 `raw_key`/`processed_key`로 찾아서 준다.
  - 기록 지우기(`deleteSession`)는 경로를 userId로 만들지 말고 저장된 `raw_key`/`processed_key`(+ A 경로)를 지운다.

### 5.5 그 밖의 서버 변경

- `GET /api/me`: `{userId, nickname, kakao: boolean}`.
- `GET /api/sessions` (새로 만듦): 내 세션 목록 `[{id, courseId, courseVersion, startedAt, endedAt, device, rawKey, processedKey, formatVersion}]`. 오래된 것부터, 한 번에 전부(수백 개 정도 가정).
- `GET /auth/providers`: `{kakao: boolean}`. 비밀값이 들어 있는지만 알려 주고, 앱은 false면 카카오 버튼을 숨긴다.
- `POST /auth/logout`: 이 요청의 폰 열쇠를 지운다.
  - `user_tokens`면 그 행을 지운다.
  - 첫 익명 열쇠(`users.token_hash`)면 아무도 모르는 무작위 값의 해시로 바꾼다. 카카오 연결이 없는 계정은 로그아웃 버튼이 없으니 이 경우는 카카오 연결된 계정뿐이다.
- CI(`.github/workflows/ci.yml`): Worker 배포 단계에서 두 GitHub 비밀값이 있으면 `wrangler secret put`으로 넣는다(값은 표준 입력으로, 로그에 안 찍히게).

### 5.6 앱 변경

- `src/app/account.ts`
  - `kakao`(연결 여부)를 폰에 저장한다.
  - `startKakaoLogin()`: verifier를 만들어 `localStorage`에 둔다. 진행 중 표시를 남기고, start를 부른 뒤 이동한다.
  - `finishKakaoLogin(state, code)`: 열쇠·userId·닉네임을 저장하고 onboarded로 표시한 뒤 되살리기를 시작한다.
  - `logout()`
  - 앱 시작 때 주소가 `#/auth/kakao…`이면, `initAccount`의 `/api/me` 확인보다 먼저 마치기를 처리한다.
- 첫 화면 `WelcomeScreen`
  - 카카오 버튼을 둔다. 카카오 디자인 가이드대로 노랑 `#FEE500`, 검정 말풍선 기호, "카카오로 시작하기".
  - 그 아래 기존 닉네임 시작을 "로그인 없이 시작"으로 둔다.
- 설정 계정 칸
  - 연결 안 됨: "카카오로 로그인" 버튼과 "로그인하면 폰을 바꿔도 기록이 돌아와요".
  - 연결됨: "카카오 연결됨 · 닉네임", "로그아웃".
  - 계정 끊김(lost) 상태에도 "카카오로 로그인"을 보인다. 카카오 연결했던 계정이면 이걸로 돌아온다.
- 로그인 화면 `#/auth/kakao`: 마치는 중, 실패, 취소, "번호 입력", "다른 창에서 끝남 → 번호 보여 주기"를 처리한다.
- 로그아웃
  - 올릴 것이 남아 있으면(대기열 > 0) 막고 "아직 올리지 못한 기록이 있어요"를 보인다.
  - 아니면 확인 창 "이 폰의 기록은 지워지고, 다시 로그인하면 되살아나요"를 띄운다.
  - 확인하면 서버 logout을 부르고, 폰 저장소(기록·원본·결과·내 코스·대기열)와 계정 정보를 지운 뒤 첫 화면으로 간다.
  - 기본 코스와 설정은 남긴다.

### 5.7 되살리기 (`src/app/restore.ts`)

- **언제**
  - 카카오 로그인을 마친 직후.
  - 카카오 연결된 계정으로 앱을 열 때마다. 목록 비교만 하고 없는 것만 받는다. 다른 폰에서 새로 탄 기록도 따라온다.
- **코스**: `GET /api/courses`의 코스 중 폰에 없거나 버전이 더 높은 것을 폰에 넣는다.
- **기록**: `GET /api/sessions` 중 폰에 없는 id를 새것부터 하나씩 처리한다.
  - `raw_key`가 없는 기록(원본 업로드 전)은 건너뛴다.
  - `/files/{userId}/{id}.raw.json.gz`를 받아 `readRawFile`로 읽는다. 합쳐진 기록은 5.4의 서버 대체로 받는다.
  - **같은 id**로 폰 기록을 만든다. `imported`가 아니라 서버에 이미 있는 기록으로 표시하고, `uploadedAt`을 넣어 다시 올리지 않게 한다.
  - 원본 조각을 넣고 `processSession`으로 다시 계산한다.
  - 다시 계산한 결과를 다시 올리지 않게, 이 기록은 업로드 대기열에 넣지 않는다.
  - 원본 정리는 기존 업로드된 기록 정리 규칙을 따른다.
- **진행 표시**
  - 상태는 `{running, done, total, failed}`.
  - 기록 탭 위와 설정에 "기록 되살리는 중 12/40"을 보인다.
  - 실패한 것은 건너뛰고 다음 앱 시작 때 다시 한다. 중간에 끊겨도 다음에 이어서 한다(폰에 없는 것만 받으니까).
- **주행 중에는 하지 않는다**. 주행이 끝난 뒤 이어서 한다.

### 5.7-1 기본 코스 (검토 지적)

- 기본 코스는 폰마다 무작위 id로 만들어지고 `builtin` 키는 폰에만 있다. 그래서 그대로 되살리면 "배후령"이 두 개가 되고 기록이 나뉜다.
- 서버 `courses`에 `builtin TEXT NULL` 열을 더한다(0003). 앱은 코스를 올릴 때 builtin 키도 올린다.
  - 예전에 올라간 행에는 키가 없다. 이름이 기본 코스와 같고 출발선이 30 m 안이면 그 기본 코스로 본다.
- 되살릴 때 서버의 기본 코스는 폰에 새 코스로 넣지 않는다.
  - 그 코스를 쓴 기록은 폰에 있는 같은 기본 코스(폰의 id, 폰의 최신 출발·도착선)로 이어 붙여 다시 계산한다.
  - 같은 기본 코스면 폰을 바꿔도 랩 기록이 한 코스에 모인다.

### 5.7-2 이 폰에만 있는 기록 (검토 지적)

- **로그인한 뒤** (최종 검토 반영)
  - 이 폰에서 계산했지만 한 번도 올리지 않은 기록만 이 계정으로 올린다(대기열에 없을 때).
  - 다른 계정(끊긴 계정 등)에 올렸던 기록은 올리지 않는다.
    - 서버에서 그 계정 것이라 403이 되고, 대기열이 영영 비지 않는다.
    - 다른 폰에서 지운 기록이 되살아날 수도 있다.
    - 대신 로그아웃 때 "이 폰에만 있는 기록"으로 알린다.
  - "PC에서 가져온 기록"(imported), 중단된 주행, 계산 전 기록은 건드리지 않는다.
  - 지우기 요청이 다른 계정의 것이라 403이면 다시 시도하지 않는다.
- **로그아웃할 때**
  - 서버에 없는 기록(가져온 기록, 원본이 없어 못 올린 기록) 수를 세어 확인 창에 보인다. 예: "이 폰에만 있는 기록 3개는 지워져요".
  - 사용자가 확인해야 진행한다.

### 5.8 보안 정리

- **state** 무작위 128비트 이상, 10분, 한 번만.
- **verifier** 시작한 폰만 안다. 서버에는 해시만 있다.
- **긴 코드** 무작위 128비트 이상. **6자리 코드**는 5번 시도 제한.
- **폰 열쇠** URL에 넣지 않는다. 마치기 응답(본문)으로만 준다.
- **returnTo** 허용 출처만. 열린 리다이렉트 금지.
- **로그** 카카오 회원번호·닉네임·위치를 Worker 로그에 찍지 않는다.
- **사용자 확인**
  - 합치기와 연결은 마치기에서만 한다(verifier + 코드 + B의 열쇠 확인 뒤).
  - A는 카카오가 확인한 회원번호로만 정한다.

### 5.9 테스트

- **Worker** (카카오 호출은 가짜 fetch)
  - 5.3 표의 각 줄.
  - state 만료·재사용, verifier 틀림, 6자리 5번 틀림, returnTo 막기, 취소.
  - 콜백만으로는 계정이 안 바뀜(공격 시나리오).
  - 합치기 뒤 A로 B 기록·파일 접근, 합친 기록 지우기.
  - 기본 코스 이어 붙이기, 폰에만 있는 기록 다시 올리기, 로그아웃 경고 수.
  - 로그아웃 뒤 열쇠 401, `/api/sessions` 남의 것 안 보임, providers.
- **앱**
  - 시작·마치기 상태 변화, 주소로 돌아왔을 때 처리 순서(계정 끊김이 안 뜸), 로그아웃 막기·지우기.
  - 되살리기: 가짜 서버로 없는 것만 받기, 같은 id, 다시 안 올림, 실패 건너뛰기, 이어서 하기.
  - 첫 화면·설정 화면 글과 버튼.
- **시안 스크린샷**: 첫 화면, 설정 두 상태, 번호 입력, 되살리는 중.

## 6. 남은 판단 (만드는 사람이 정함)

- 화면 글귀 세부, 카카오 버튼 크기와 위치 세부, 되살리기 진행 표시 모양. 시안으로 사용자 확인을 받는다.
