# 도움말 · 기능 알아보기 설계

2026-11-18 · 세영 "설정에 도움말 기능에서 기능 알아보기를 스크린샷, 짧은 gif로 기능 설명하는 페이지 만들어봐".
시안: `docs/mock/2026-11-18-help.jpg` (세영 "a" — A 방식 승인).

## 세영 결정

- 보는 사람: **처음 깐 사람**과 **나중에 기능이 궁금한 사람** 둘 다
- 움직이는 그림(GIF)은 **2개**만, 나머지는 스크린샷
- **정식 기준**으로 만든다. **친구 위치 공유 설명은 뺀다** (테스트 빌드에서도 같은 페이지)

## 방식 (고른 것: A)

| | 방식 | 장단 |
|---|---|---|
| **A (고름)** | 한 페이지에 기능 카드를 쭉. 맨 위 "처음이세요? 3단계", 칩을 누르면 그 카드로 | 처음 사람은 위에서부터, 궁금한 사람은 칩으로 바로. 한 화면이라 고치기 쉬움 |
| B | 한 장씩 넘기는 카드 | 첫 안내엔 좋지만 나중에 찾아보기 불편 |
| C | 넘기는 첫 안내 + 목록 페이지 따로 | 둘 다 좋지만 만들 양·고칠 곳 두 배 |

세영이 방식을 따로 고르지 않고 "만들어"라고 해서 추천 A로 (Claude 판단).

## 화면

- **설정**: "약관" 바로 위에 "도움말" 칸 → "기능 알아보기 · 그림으로 보는 디고 사용법" (`#/help`)
- **메인**: 처음 깐 사람에게 위쪽에 작은 알림 "디고 처음이세요? 그림으로 기능을 알아봐요 [기능 알아보기] ✕" — 누르거나 ✕ 하면 다시 안 뜸 (폰에 기억). 팀 주행 알림이 떠 있으면 그것이 먼저 (Claude 판단: 처음 사람은 설정까지 잘 안 들어가서)
- **기능 알아보기** (`#/help`): 뒤로 · 제목 → "처음이세요? 3단계면 돼요" → 기능 칩(가로로 밀기) → 카드들. 카드 = 제목 · 그림 · 2~3줄 · (있으면) 바로 가기

## 그림 만들기

- 앱스토어 스크린샷과 같은 방법: 정식 스위치로 띄운 앱 + 예시 자료(이름·사진 예시) + 실제 서버 지도. 실제 화면에서 필요한 부분만 잘라 카드 폭에 맞춘다
- 스크린샷: 가로 약 720 px JPEG, 장당 100 KB 안팎. 움직이는 그림: 가로 약 360 px, 초당 10장, 3~4초 반복 GIF, 장당 1.5 MB 이하
- `public/help/`에 둔다 (앱 안에 들어가 통신이 없어도 보임). 합쳐서 약 3~4 MB
- 다시 만들 수 있게 만드는 대본을 저장소에 둔다 (Claude 판단)

## 그대로 / 안 함

- 팀 주행·약관 등 기존 화면은 그대로. 웹에도 같은 페이지(웹 배포는 따로 묻기)
- 친구 위치 공유, 앞 친구 간격 설명은 넣지 않는다

## 시험

- 설정 "도움말 › 기능 알아보기" 링크, `#/help` 카드 순서·칩 누르면 그 카드로, 바로 가기 주소
- 메인 알림: 처음 한 번, 누르거나 ✕ 뒤 안 뜸
- 페이지에 "위치 공유" 글자 없음, 그림 파일이 다 있고 크기 한도 안
