# M7 계획: 사양서 v2 반영 + 확장 지점

사양서 v2(14장)의 1단계 새 항목과 13장 확장 지점. 사용자 확인: "구현해야해 건너뛰지않아", M6 뒤 "둘 다 진행".

## 작업
1. 사양서 합치기: 원본(v1)·v2·대화 결정(저장소 사양서)을 3방향으로 합친다. 충돌 7곳은 v2 구조를 뼈대로 대화 세부를 넣는다. 서버는 Cloudflare 하나 그대로. 변경 이력은 v2의 14장 아래에 대화 결정 표를 붙인다.
2. `ui/overlay/`: "시각 t의 주행 상태 → 캔버스" 그리기 함수(델타·속도·G·미니맵). 주행 화면 지도 모드가 이것을 쓴다(겉모습은 그대로). 13.1 영상에 입히기가 같은 함수를 쓴다.
3. 메인 지도: 통신이 되면 OSM 타일(Leaflet) 위에, 안 되면 타일 없이 격자 위에 코스 선·출발선·내 위치. 출처 표시, 서비스 워커는 타일을 쌓아 두지 않는다(OSM 이용 정책).
4. 처리된 궤적 파일에 `utc`(GPS 기준 절대 시각)·`hAcc` 열 (13.1 확장 지점, 6.9 CSV 준비).
5. 원본 파일·폰 덩어리에 `channels` 자리 (13.2 OBD 확장 지점).
6. 고스트 위치 테스트 보강: 가상 데이터에서 고스트의 코스 거리가 비교 랩의 실제 위치와 맞는지 (10.1).

## 완료 확인
- 테스트·타입 검사·빌드·CI, 재생 모드 화면 캡처(지도 모드 겉모습이 전과 같은지), 메인 지도 캡처(타일 있음·없음), 폰 확인.

## 결과 (2026-11-12)
1. 사양서: 3방향 합치기 충돌 7곳 해결. v2 구조 + 대화 세부, Supabase 언급 정리(D1). 변경 이력은 v2 14장 아래에 대화 결정 표.
2. `src/ui/overlay/`: `frame.ts`(시각 t의 상태, 델타 글자·값 칸), `draw.ts`(델타 패널·값 칸·G미터·G 칸, 바탕 선택), `minimap.ts`(코스 선·게이트·고스트·내 위치·지나온 경로), `theme.ts`(델타 색 설정 두 가지). 지도 모드 주행 화면이 `OverlayCanvas`로 이 함수들을 부른다. 시안(HTML)과 겹쳐 보며 위치를 맞춰 세로·가로 모두 겉모습이 같다. 테스트는 그리기 호출을 기록하는 가짜 캔버스로.
3. 메인 지도: Leaflet 1.9.4 + OSM 타일(어둡게 뒤집음). 통신이 없거나 타일이 6번 연달아 실패하면 타일을 빼고 격자. 코스 선·출발선(편도면 도착선)·내 위치와 정확도 원. Leaflet은 따로 불러오는 묶음(gzip 44 KB). 지도 출처 표시, 버전은 왼쪽 아래로. 이 작업 공간에서는 OSM 서버에 닿지 않아 가짜 타일로 배치만 확인했다 → 실제 지도 모양은 폰에서 확인.
4. 처리된 궤적 `utc`(t + 중앙값(tFix − tRecv), 기기 시계가 하루 넘게 틀리면 세션 시작 기준)·`hAcc`(GPS 점 사이 선형 보간). 테스트: GPS 지연 180 ms에서 정답과 ±40 ms, 단조 증가, 시계 오류 시 대체.
5. 원본 파일·폰 덩어리 `channels` 자리: 이름별로 seq 순서대로 이어 붙임, 없는 예전 파일도 읽음.
6. 고스트 위치: 가상 첫 주행(정답을 앎)을 비교 랩으로 두 번째 주행을 흘려보내, 고스트가 비교 랩이 같은 랩 경과 시간에 실제로 있던 곳과 위치 RMS 2.5 m·최대 4.5 m, 코스 거리 RMS 1.7 m. 고스트 시각을 3% 틀리게 하면 21 m로 실패하는 것을 확인.
