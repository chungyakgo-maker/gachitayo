# M5 계획: 주행 준비 · 주행 화면 · 종료 요약 · 재생 모드

사양서 5.3, 7.2(재보정), 8.2~8.5, 8.8 일부, 10.2. 화면은 승인된 디자인 시안(2026-11-12) 그대로.

## 결정 사항 (사용자 확인: 시안대로, 추천대로)

1. 주행 화면에 **지도 모드**를 더한다(기본). 지도 타일 없이 코스 선, 내 위치, 베스트 고스트.
2. 친구·위치 공유 관련 표시(위치 공유 버튼, 같이 달리기, 친구 칩, 앞 친구 간격)는 1단계에서 뺀다.
3. 시안의 추가 기능: 상단 표시 값 두 칸, 대시보드 구간별 델타, 델타 색 설정.
4. 랩타임 표기: 끝난 랩 소수 셋째 자리, 진행 중 랩 첫째 자리.
5. 홈은 아래 탭(메인/코스/기록/설정). 업로드 대기는 메인에 한 줄(M6에서 연결).
6. 재보정 '나': 주행 중 재보정은 직선 등속 3초도 정차처럼 인정.
7. 기록은 **주행 준비 화면에 들어올 때 시작**한다. 센서가 켜져야 GPS 준비·거치 보정을 보여줄 수 있고, 그 정차 구간이 주행 후 거치 보정에도 쓰인다. 준비에서 취소하면 그 기록을 지운다.

## 범위 밖 (다음 마일스톤)
- 업로드·동기화, 닉네임·익명 계정(M6). 요약의 업로드 줄은 "폰에 저장됨"만 보여준다.
- 분석 화면, 코스 편집(선 옮기기·이름 바꾸기·다듬기)·지도 등록·GPX 화면, 설정의 게이트 폭·동기화(M7). 코스 탭과 기록 탭은 목록만.

## 작업 목록

### A. 실시간 계산 (순수 엔진, 테스트 먼저)
1. **LiveMotion50** (`normalize/liveMotion.ts`): 모션 원본이 들어올 때마다 50 Hz 격자를 채우는 늘어나는 Motion50. 같은 원본이면 `resampleMotion`과 같은 값. `MotionWindows`가 늘어나는 배열을 따라가게 고친다.
2. **과거만 쓰는 GPS 관측** (`toLiveGpsObs`): 속도가 없는 점은 뒤쪽 2점 위치 차이로 계산.
3. **직선 등속 재보정** (`MountCalibrator`): 재보정 뒤 아래 방향은 정차 3초 또는 직선 등속 3초(GPS 속도 5 m/s 이상, 속도 변화·방향 변화가 작음)로 구한다. 서킷에서 멈추지 않고 거치가 바뀐 뒤 다시 보정되는지 테스트.
4. **LivePipeline** (`engine/live/livePipeline.ts`): GPS 준비 판정 + LiveMotion50 + 보정기 + FusionRunner + LiveEngine을 묶는다. `pushGps`, `pushMotion`, `tick(t)` → 화면용 스냅숏(LiveState, 내 위치·방향, GPS 준비·오차, 보정 상태·정차 진행률, 고스트 위치, 첫 주행 경로).
5. **고스트 위치**: 비교 랩 trace에서 지금 랩 경과 시간과 같은 시각의 코스 거리 → 중심선 위 점.
6. **구간 델타·최고 속도**: LiveEngine에 비교 랩 구간 기록을 넘겨 끝난 구간은 (구간 기록 − 비교 구간), 지금 구간은 (지금 델타 − 구간 시작 때 델타). 세션 최고 속도.
7. 확인: 가상 주행(첫 주행 → 코스·베스트 → 두 번째 주행)을 원본 샘플 단위로 LivePipeline에 흘려 보정 완료, 랩 검출, 델타 RMS < 0.3초(실시간 보정 포함), 고스트 위치 오차.

### B. 저장소와 주행 흐름
1. **Dexie v2**: `results`(세션별 주행 후 처리 결과), `courses`, `refLaps`(코스·버전별 유효 랩 trace·구간). `sessions`에 `courseId`, `courseVersion`, `summary`. 세션 삭제(준비 취소).
2. **설정** (폰 보관): 기본 화면 모드, 상단 표시 값 두 칸, 델타 색.
3. **주행 컨트롤러** (`app/drive.ts`): 준비(기록 시작 + 실시간 계산 연결 + 코스 감지 + 비교 랩) → 주행(`drive_start` 이벤트) → 종료(기록 종료 → 원본 읽기 → 주행 후 처리를 **Web Worker**에서 → 결과·비교 랩 저장) → 요약. 첫 주행이면 코스 저장 폼(종류를 바꾸면 다시 처리).
4. 기록 컨트롤러에 샘플 구독(`subscribeSamples`)을 더해 실시간 계산이 같은 센서 값을 받는다.
5. **재생 모드** (개발자 메뉴): 저장된 세션 또는 가상 주행을 1×/5×/10×로 실시간 계산에 흘려 주행 화면을 본다(기록·저장 없음).

### C. 화면 (시안 그대로)
1. 글꼴: `@fontsource/ibm-plex-sans-kr`, `@fontsource/ibm-plex-mono`를 앱에 넣고, 글꼴 파일은 서비스 워커가 처음 받을 때 보관(오프라인에서도 보임). 색·크기는 CSS 변수로.
2. 앱 틀: 아래 탭(메인/코스/기록/설정), 라우트 `/`, `/courses`, `/history`, `/settings`, `/prepare`, `/prepare/widgets`, `/drive`, `/summary/:id`, `/dev/recorder`, `/dev/replay`.
3. 메인: 감지된 코스 카드, 주행 시작, 타일 없는 지도(격자·코스 선·출발선·나).
4. 주행 준비, 상단 표시 값.
5. 주행: 지도 / 미니멀 / 대시보드, 두 번 탭으로 모드 전환, 2초 길게 눌러 종료(진행 표시), 랩 통과 3초 크게, GPS·코스 이탈·G 보정 상태.
6. 종료 요약: 처리 중 표시 → 베스트·개인 기록 갱신·이론상 베스트·유효 랩·랩 표, 첫 주행이면 새 코스 저장 폼(편도면 작은 지도).
7. 코스 탭(목록), 기록 탭(목록 → 요약 다시 보기), 설정 탭(기본 모드, 상단 값, 델타 색, 개발자 메뉴).
8. 확인: 화면 컴포넌트 테스트(jsdom) — 모드 전환, 길게 눌러 종료, 표시 값 바꾸기(같은 값이면 서로 바뀜), 랩타임 표기, 델타 색. 브라우저(Playwright)로 재생 모드를 돌려 각 화면 스크린숏을 찍어 시안과 비교.

## 결과 (2026-11-12)

- 자동 테스트: 실시간 계산 묶음(가상 주행 원본을 샘플 단위로 흘림), 저장소 v2, 주행 후 처리·코스 저장 흐름, 화면 컴포넌트(모드 전환·길게 눌러 종료·표기·상단 값 바꾸기·요약).
- 주행 중 델타 정답 대비 (오벌, 3% 느린 두 번째 주행, 실시간 거치 보정 포함, 시드 3개): RMS 0.08~0.12초, 최대 0.27~0.60초. 주행 후 처리 기준(사양서 10.1, RMS 0.15초) 안.
- 주행 중 G값은 출발 뒤 약 29초(코너 몇 번으로 축 부호 확인)부터 나온다.
- 직선 등속 재보정(결정 6): 서킷에서 멈추지 않고 거치가 20° 돌아가도 다시 보정, 각도 오차 1.4°. 함께 앞 방향 직진 판단을 자이로 0.5초 조각으로 바꿔 보고서의 거치 각도 오차도 줄었다(1.5°→0.9° 등).
- 브라우저(Chromium, 390×844)에서 재생 모드로 메인 → 주행 3모드 → 요약을 찍어 시안과 비교. 위치를 실제 시간으로 움직여 주행 시작 → 기록 시작 → 길게 눌러 종료 → Web Worker 계산 → 요약까지 확인.
- 브라우저 시험에서 발견: GPS가 속도·진행 방향 값을 둘 다 주지 않으면(PC 브라우저, 일부 안드로이드) 융합이 방향을 잃고 발산했다(주행 중 위치 RMS 77 m, 주행 후 코스 길이 −15%). 위치 이동 방향으로 대신하도록 고쳐 주행 중 약 9 m, 주행 후 코스 길이 3% 안. 값을 주는 폰은 영향 없음.
- 남은 일(다음 단계): 업로드·동기화(M6), 분석·코스 편집·GPX 화면(M7). 메모리: 2시간 주행이면 50 Hz 모션 격자와 누적합이 약 45 MB — 실차 테스트에서 문제가 되면 고리 버퍼로 바꾼다.
