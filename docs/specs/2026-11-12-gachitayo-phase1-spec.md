## 0. 구현자(Claude Code)에게

- 사용자는 개발 초보다. **로컬 PC에서 터미널, PowerShell, 스크립트를 실행하지 않는다.**
  - 빌드, 테스트, 배포: 전부 GitHub Actions에서 돌아가야 한다.
  - 서버 설정: 전부 브라우저(Cloudflare 대시보드, GitHub 웹)에서 할 수 있어야 한다.
- 사용자가 직접 실행할 SQL은 **채팅에 코드 블록으로 붙여서** 전달한다. 파일로 주지 않는다. 저장소에 참고용 사본은 둬도 된다.
- 코드를 작성하거나 수정하기 전에 계획을 먼저 보여주고 확인을 받는다.
- 이 문서의 숫자 기준값(임계값)은 **초기값**이다. 한 곳(`src/engine/config.ts`)에 모아서 실측 후 조정할 수 있게 한다.
- 13장 "1단계 이후 추가 기능"은 1단계가 끝난 뒤 적힌 순서대로 진행한다. 1단계 구현 중에는 13장 각 항목의 **"1단계에서 남겨둘 확장 지점"만** 반영하고, 기능 자체는 만들지 않는다.

## 1. 목적과 성공 기준

**목적:** 와인딩·서킷 주행에서 폰 하나로 주행 경로와 센서 데이터를 기록한다. 같은 코스의 이전 랩(고스트)과 비교한 델타를 실시간으로 보여주고, 주행 후에 분석한다. 지도는 보조 역할이다.

**사용자:** 본인과 친구 몇 명이 데모로 쓴다. 아이폰과 안드로이드를 섞어서 쓴다.

**1단계 성공 기준**
1. 아이폰(Safari)과 안드로이드(Chrome) 모두에서, 홈 화면에 설치한 뒤 20분 주행을 끊김 없이 기록한다.
2. 랩 자동 감지, 랩타임, 3구간 기록, 이론상 베스트를 계산한다.
3. 같은 코스 두 번째 주행부터 내 베스트 랩 대비 실시간 델타를 표시한다.
4. 통신이 없어도 기록과 델타가 동작하고, 통신이 돌아오면 자동으로 업로드한다.
5. 서킷 공식 계측 대비 랩타임 오차 ±0.3초 이내 (1차 목표, 실측으로 검증).
6. 분석 화면: 랩 목록, 속도·델타·고도 그래프, 속도 색칠 지도, G 다이어그램, 지점 정보.
7. 주행 중 메인 화면(지도 모드): 상단에 델타와 사용자가 고른 값 2칸, 하단에 코스 선·내 위치·베스트 고스트가 보인다.
8. CSV 내보내기: Telemetry Overlay, RaceRender 같은 영상 오버레이 프로그램의 사용자 지정 CSV로 읽을 수 있다.

## 2. 전체 로드맵과 1단계 범위

| 단계 | 내용 |
|---|---|
| **1단계 (이 문서)** | GPS·센서 기록, 코스 만들기 3가지, 내 기록끼리 고스트 델타, 통합 메인 화면(하단 지도), 주행 화면 3모드(지도/미니멀/대시보드), 상단 표시 값 선택, 주행 후 분석, 익명 로그인, 폰 저장 → 서버 동기화(D1 표 + R2 파일), GPX 불러오기·내보내기, CSV 내보내기, **친구 코드 + 위치 공유(본인이 켠 동안만) + 메인 지도에 공유 중인 친구 표시** (M8: 사용자 요청으로 2단계에서 앞당김), **앞 친구 간격(초)을 델타처럼** (M9: 사용자 요청으로 3단계에서 앞당김, 어디서나·목표 1초 이상) |
| 1단계 직후 | 13장의 추가 기능. 순서 (사용자 결정 "가"): 지금 웹앱으로 짧게 실차 측정(저속 루프 2~3번, 원본으로 기준값 다듬기) → Expo 전환(+OBD) → 영상에 입히기. 웹 전용 항목(20분 연속 기록, 1주일 방치 뒤 업로드 등)은 Expo 앱에서 시험한다 |
| 2단계 | 정식 로그인(구글·카카오 등을 익명 계정에 연결), 로그인·닉네임 뒤 **개인 정보(이름, 차종 등)** 설정 (사용자 요청, 나중 반영), 크루, 기록 공유, 친구 고스트, 크루 코스별 순위표, 파일 게이트웨이에 친구·크루 권한 확인 추가 (친구 코드와 위치 공유는 1단계 M8로 옮김) |
| 3단계 | 방 코드로 입장("같이 달리기"), **방장이 그룹 주행 순서와 차간 목표 간격(초)을 정하고, 방 인원끼리 주행 중 서로의 간격 델타를 공유** (사용자 요청, 나중 반영. M9의 앞 친구 간격·실시간 방을 넓힌다), 여러 명이 서로 앞뒤 간격 보기(서킷 전용), 주행 중 지도에 같이 달리는 친구 모두와 "닉네임 앞/뒤 N초" 표시 (앞 친구 한 명과의 간격은 M9에서 넣음. 공유 중인 친구들의 점과 닉네임은 사용자 요청으로 1단계에 넣음, 5초 간격) |

**1단계에서 하지 않는 것**
- 외부 GPS나 블루투스 기기
- 가민 등 시계 연동, 심박
- 음성 안내
- 크루, 실시간 기능 (친구 코드·위치 공유는 M8에서 넣음)
- 정식 로그인, 로그아웃
- 네이티브 앱

**1단계 이후 추가 기능:** 13장에 순서와 상세를 적었다 (영상에 입히기, OBD 연동, Expo 전환, 기타).

## 3. 확정된 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 앱 형태 | 웹앱(PWA), 홈 화면 설치 | 코드 하나로 아이폰·안드로이드 지원, 링크로 배포, 비용 없음 |
| 위치 센서 | 폰 내장 GPS만 사용 | 외부 GPS는 쓰지 않음. 아이폰 사파리는 웹 블루투스를 지원하지 않음 |
| 정확도 확보 | 센서 융합, 게이트 통과 보간, 코스 선 투영, 주행 후 재계산 | 1Hz GPS의 한계 보완 |
| 저장 | 폰에 먼저 저장 → 서버에 동기화 | 서킷 통신 끊김 대비, 데이터 보존, 2단계 기반 |

| R2 접근 | Cloudflare Worker(파일 게이트웨이)를 거쳐서만 | R2 접근 키를 브라우저에 두지 않기 위해 |

| 코스 만들기 | 첫 주행 자동 생성, 지도 등록, GPX 불러오기 | 지도는 보조이므로 "그냥 달리기"가 기본 |
| 코스 종류 | 랩(서킷), 편도(와인딩) | 출발점과 도착점 거리로 자동 구분하고 사용자가 확인 |
| 메인 화면 | 앱을 열면 나오는 통합 화면. 지도가 화면 전체이고 위쪽 카드(상태·주행 시작)와 아래 탭은 반투명으로 얹는다. 내 위치는 가려지지 않은 지도의 가운데 (사용자 요청) | 지도를 보조로 두되 항상 위치와 코스를 보여준다 |

| 분석 | 랩 목록, 이론상 베스트, 속도·델타·고도 그래프, 속도 색칠 지도, G 다이어그램 | |
| 지도 | Leaflet + OpenStreetMap, 위성 보기는 옵션 | API 키 불필요 |

| 계산 엔진 | 화면과 분리된 순수 TypeScript | 녹화 데이터로 자동 테스트 가능, Expo로 옮길 때 재사용 |

## 4. 기술 스택

- **언어·UI:** TypeScript(strict), React, Vite
- **PWA:** vite-plugin-pwa (매니페스트, 서비스 워커). 앱 화면은 오프라인 캐시로 통신 없이도 열린다.
  - 새 버전은 메인 화면에서 주행·기록 중이 아니면 저절로 적용한다 (사용자 불편: "업데이트"를 눌러야만 들어와서 고친 화면이 폰에 늦게 보였다). 주행·기록 중에는 적용하지 않고(기록이 끊기지 않게), 끝나고 메인으로 돌아오면 적용한다. 같은 앱을 연 다른 창에서 업데이트해도 주행 중인 창은 새로고침하지 않는다. 저절로 적용이 안 되면 "업데이트" 버튼으로 적용한다.
- **라우팅:** 해시 라우팅. GitHub Pages 하위 경로와 새로고침 404 문제를 피한다.
- **폰 저장소:** IndexedDB (Dexie 같은 래퍼 사용)
- **서버:** Cloudflare Worker(TypeScript: 익명 계정, 표 API, 파일 게이트웨이) + D1(SQLite, 표) + R2(파일). M6 결정 (원래 Supabase)
- **파일 저장:** Cloudflare R2 + Cloudflare Worker (TypeScript, 파일 게이트웨이)
- **지도:** Leaflet + OSM 타일
  - OSM 타일 이용 정책은 소규모 데모 수준에서 지킨다.
  - 위성 보기는 이용약관이 허용하는 제공자만 쓰고, 출처를 표기한다.
- **차트:** 점이 많아도 가벼운 라이브러리 (예: uPlot)
- **압축:** 브라우저 내장 CompressionStream(gzip)
- **테스트:** Vitest (엔진 단위 테스트)
- **CI/CD:** GitHub Actions
  - 푸시와 PR마다 타입 검사와 테스트를 실행한다 (웹앱과 Worker 모두).
  - main에 푸시되면 서버를 Cloudflare에 배포하고(공식 wrangler CLI: R2 버킷·D1 데이터베이스가 없으면 만들고, D1 표 마이그레이션 적용, Worker 배포), 그 Worker 주소를 넣어 웹앱을 빌드해 GitHub Pages에 배포한다.
  - 테스트가 실패하면 배포를 중단한다.
- **환경 변수와 비밀값 (모두 GitHub 웹에서 등록):**
  - Actions 비밀: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` (이 둘만 등록하면 된다)
  - 웹앱의 서버 주소 `VITE_API_URL`은 배포 때 Worker 주소를 받아 자동으로 넣는다. 필요하면 Actions 변수 `VITE_API_URL`로 덮어쓸 수 있다.
  - Worker 설정값 `ALLOWED_ORIGIN`(GitHub Pages 출처 `https://{주인}.github.io`)과 D1 데이터베이스 ID는 `wrangler.toml`에 적지 않고 배포 때 넣는다 (사용자가 파일을 고칠 필요가 없게).
  - 비밀값이 아직 없으면 서버 배포를 건너뛰고, 웹앱은 폰에만 저장한다(첫 실행의 계정 만들기도 건너뜀).

| 10 | 서버 (`worker/`) | 익명 계정(폰 열쇠) 발급·확인, 표 API(본인 행만), 파일 게이트웨이(본인 폴더의 R2 파일만) | Cloudflare Worker, D1, R2 |
| 11 | 내보내기 (`export/`) | 세션을 CSV로 만들기 (6.9) | 순수 TS |
| 12 | 오버레이 그리기 (`ui/overlay/`) | "시각 t의 주행 상태"를 받아 델타·속도·G·미니맵을 캔버스에 그리는 함수. 주행 화면의 지도 모드와 13.1 영상에 입히기가 같이 쓴다 | 캔버스 |

**규칙:** `engine/*`, `normalize/`, `gpx/`는 DOM, 브라우저 API, 서버를 직접 쓰지 않는다.
- 입력도 데이터, 출력도 데이터다. 같은 입력이면 항상 같은 출력이 나온다.
- 그래서 Node 환경의 Vitest에서 테스트할 수 있고, Expo로 옮길 때 그대로 재사용한다.

### 5.3 주행 중 흐름

```
센서 수집 → 공통 기준 변환 ─┬→ 메모리 버퍼 → (5초마다) 폰 저장소
                            └→ 융합(실시간 필터) → 코스 엔진(코스 거리, 게이트)
                                → 델타 엔진 → 주행 화면 (10Hz 갱신)
```

### 5.4 주행 후 흐름

1. 주행을 끝내면 폰에 있는 원본 전체로 융합 스무더를 다시 돌린다.
2. 랩, 구간, 비교용 축약 데이터, 처리된 궤적을 확정한다.
3. 결과를 폰 저장소에 저장한다.
4. 동기화로 업로드한다.
   - 원본과 처리된 궤적 파일을 먼저 파일 게이트웨이를 거쳐 R2에 올린다.
   - 파일 업로드가 성공하면 세션과 랩 요약을 서버 표(D1)에 넣는다.
   - 이 순서 덕분에 표가 존재하지 않는 파일을 가리키는 일이 생기지 않는다.

## 6. 데이터 명세

### 6.1 시간 기준

- 세션을 시작할 때 `performance.now()`와 `Date.now()`를 한 쌍으로 기록한다.
- 모든 샘플 시각은 단조 증가 시계(ms)로 저장한다. 화면과 파일에 표시할 때 절대 시각으로 바꾼다.
  - 저장하는 값은 "세션 시작부터 ms"(세션 시계)다.
  - 앱이 중단됐다가 이어서 하면 새 페이지의 단조 시계는 0부터 다시 시작하므로, 벽시계 차이(`Date.now() − startedAt`)로 이어 붙인다. 벽시계가 뒤로 가 있어도 마지막 샘플 시각보다 작아지지 않게 한다.
- GPS 샘플은 두 시각을 모두 저장한다.
  - 수신 시각(`tRecv`, 단조 시계)
  - `position.timestamp`(`tFix`)
- 융합은 수신 시각을 기준으로 한다. 두 시각의 차이(지연)는 기록해 두었다가 실측 후 보정에 쓴다.

### 6.2 샘플 형식 (내부)

**GpsSample**

- `pause`/`resume`은 화면이 가려질 때와 다시 보일 때 자동으로 남긴다. 중단 후 이어서 하기의 `resume`에는 `afterInterruption: true`를 붙인다.

> 원본 파일에는 **기기 축 원본**을 저장한다. 차 기준 값은 거치 보정 결과(회전 행렬)로 언제든 다시 계산한다. 그래야 주행 후에 보정을 다시 할 수 있다.

### 6.3 플랫폼 정규화

- **모션 이벤트:** `accelerationIncludingGravity`(m/s²)와 `rotationRate`(deg/s → rad/s)를 쓴다.
  - 이벤트 간격이 기기마다 다르므로 선형 보간으로 50Hz에 맞춘다.
- **축 방향·부호 차이:** 거치 보정이 데이터에서 중력 방향과 전진 방향을 직접 찾기 때문에 대부분 자동으로 흡수된다.
  - 그래도 플랫폼별로 부호가 뒤집힌 축이 있는지 실측으로 확인한다.
  - 있으면 정규화 단계에 플랫폼별 보정표를 둔다.
  - 보정 뒤 자동 확인도 한다 (7.2-7): 앞뒤 가속도가 GPS 속도 변화와 같은 방향인지, 코너에서 요레이트·좌우 가속도 부호가 GPS 진행 방향 변화와 맞는지. 확인 전에는 융합에 모션을 쓰지 않는다.
  - 회전 값이 일부 샘플에만 빠지는 기기도 있으므로 자이로 유효 여부는 샘플마다 판단한다.
- **아이폰 모션 권한:** `DeviceMotionEvent.requestPermission()`은 반드시 버튼 탭 처리 안에서 호출한다.
- **GPS 속도나 방향이 null인 기기:** 위치 차이로 계산해서 대체하고, 세션에 "속도 품질 낮음"을 표시한다.
  - 속도는 주행 후 처리에서는 앞뒤 2점씩(약 4초) 떨어진 위치 차이로, 주행 중에는 바로 앞 점과의 위치 차이로 계산한다. 잡음이 커서 융합의 속도 관측으로는 쓰지 않는다.
  - 방향 값이 없으면 위치 이동 방향(6m 넘게 움직였을 때, 주행 후 처리는 앞뒤 점, 주행 중은 바로 앞 점)으로 대신하고, 융합에서는 표준편차 15°로 약하게 쓴다. 이것이 없으면 융합이 방향을 잃고 발산한다 (M5에서 발견: 주행 중 위치 오차 RMS 77m → 9m).
  - 정차 판단은 4초 동안의 위치를 직선 맞춤한 속도가 2 m/s 미만인지로 한다 (출발 직후 가속을 정차로 착각하지 않게).
  - 이런 기기는 주행 중 재보정 판단을 하지 않는다. 주행 후 처리에서 정차 때 중력 방향이 바뀐 지점으로 나눈다.
  - 위치 변화의 20% 넘게 계산값이면 "속도 품질 낮음"으로 본다.
- **기기 정보:** OS, 브라우저, user agent를 세션에 기록한다.

**친구 (M8, `worker/migrations/0002_friends.sql`)**
- `users.friend_code`: 8자리(헷갈리는 0·O·1·I·L 없는 31글자, 약 8.5×10¹¹가지), 처음 친구 화면을 열 때 만든다. 화면에는 `K7P2-Q9XM`처럼 4자리씩 보여주고, 넣을 때는 소문자·하이픈·공백을 다듬는다.
- `friends (user_id, friend_id, created_at)`: 코드를 넣으면 바로 서로 친구(두 방향 행). 끊으면 두 행 모두 지운다. 한 사람 50명까지. 내 코드는 넣을 수 없다.
- `friend_code_misses`: 틀린 코드는 1시간에 20번까지 (넘으면 429). 코드를 짐작해 맞히는 것을 막는다.
- `presence (user_id, lat, lon, h_acc, heading, speed, at)`: 사람마다 **마지막 위치 하나만** 둔다(이동 경로는 저장하지 않는다). 공유를 끄면 지운다. 친구에게는 2분 안에 받은 위치만 준다(그보다 오래되면 보이지 않는다).
- 순서: 코스 → 원본·처리된 궤적 파일(PUT 뒤 HEAD로 크기 확인) → 세션 → 랩. 첫 주행에서 코스를 저장하지 않은 세션은 `course_id` 없이 올리고, 나중에 저장하면 다시 올려 연결한다.
- 업로드 대기열의 재시도 간격은 10초부터 두 배씩, 최대 30분이다. 앱 시작·통신 복구·화면 복귀·주행 처리 직후·1분마다 시도한다.

- 파일은 R2에 둔다 (6.6).

### 6.6 파일 저장소 (Cloudflare R2 + 파일 게이트웨이)

**R2 버킷 `gachitayo-sessions`** (비공개, 공개 URL을 쓰지 않음)
- 원본: `{user_id}/{session_id}.raw.json.gz`
- 처리된 궤적: `{user_id}/{session_id}.processed.json.gz`

**파일 게이트웨이 (Cloudflare Worker)**
- 웹앱은 R2에 직접 접근하지 않는다. R2 접근 키는 어디에도 두지 않고, Worker의 R2 바인딩(`SESSION_FILES`)으로만 접근한다.
- 모든 요청에 `Authorization: Bearer <폰 열쇠>`가 있어야 한다.
- **열쇠 확인:** 열쇠의 SHA-256 값으로 `users`에서 사용자를 찾는다. 그 사용자 ID가 `sub`다. (원래 Supabase 토큰을 JWKS로 검증하던 것을 M6에서 바꿈)

| 요청 | 동작 | 권한 |
|---|---|---|
| `PUT /files/{userId}/{sessionId}.{kind}.json.gz` | 파일 저장. 같은 키면 덮어씀 | `sub == userId` |
| `GET` 같은 경로 | 파일 내려받기 | 1단계: `sub == userId` (2단계에서 친구·크루 확인 추가) |
| `HEAD` 같은 경로 | 존재와 크기 확인 (업로드 확인용) | 위와 같음 |

- **경로 검사:** `userId`와 `sessionId`는 UUID 형식만, `kind`는 `raw` 또는 `processed`만 허용한다. 그 외는 400을 돌려준다.
- **크기 제한:** 파일 하나당 20MB
- **CORS:** `ALLOWED_ORIGIN`(GitHub Pages 주소)만 허용하고 사전 요청(OPTIONS)을 처리한다.
- **응답 코드:** 401(열쇠 없음·무효), 403(다른 사람 폴더·허용하지 않은 출처), 404(없음), 413(너무 큼)

### 6.7 파일 형식

**원본 파일:** gzip으로 압축한 JSON, 열 단위 배열
```
{ formatVersion: 1, sessionId, startedAtEpochMs, device, calibration,
  gps:    { tRecv: [], tFix: [], lat: [], lon: [], alt: [], altAcc: [], hAcc: [], speed: [], heading: [] },
  motion: { t: [], gax: [], gay: [], gaz: [], rx: [], ry: [], rz: [] },
  events: [ … ],
  channels: { } }
```
- 소수 자릿수 제한: 위경도 7자리, 가속도와 회전 속도 3자리, 나머지 2자리
- `course`(선택): 분석 화면에서 PC용으로 내보낼 때만 넣는 그 기록의 코스. 서버 원본 파일에는 없다 (M10)
- `channels`: 추가 센서 채널 자리(13.2 확장 지점). 이름마다 `{ t: [], v: [] }`(t는 세션 시계 ms, 예: `obd_rpm`). 폰 저장소의 덩어리에도 같은 자리가 있고, 파일을 만들 때 이름별로 이어 붙인다. 1단계에서는 비어 있다. 이 자리가 없는 예전 파일도 읽는다 (M7)

**처리된 궤적 파일:** 주행 후 스무더 결과를 10Hz로 담는다.
- 열: `t`, `utc`, `lat`, `lon`, `alt`, `speed`, `heading`, `ax`, `ay`, `s`(코스 거리), `lapNo`, `hAcc`
  - `utc`: GPS 기준 절대 시각(epoch ms). 융합 시각은 GPS 수신 시각 기준이므로 `t + 중앙값(tFix − tRecv)`로 정한다. 그 값이 세션 시작 시각과 하루 넘게 어긋나면(기기 시계 오류) `startedAt + t`를 쓴다. CSV `utc_time`(6.9)과 13.1 영상 싱크의 기준 (M7)
  - `hAcc`: 그 시각 앞뒤 GPS 점의 수평 정확도를 선형 보간한 값(m). CSV `gps_acc_m` (M7)
  - M7 전에 처리한 결과에는 `utc`·`hAcc`가 없다. 다시 처리하면 생기고, 없을 때 CSV는 `startedAt + t`와 빈칸을 쓴다.
- 분석 화면의 지도, 지점 정보, G 다이어그램이 이 파일을 쓴다.

### 6.8 비교용 축약 데이터 (`laps.trace`)

- 코스 거리 5m 간격 격자 위의 값이다: `{ stepM: 5, t: [], v: [], alt: [] }`
  - `t`: 랩 시작부터 경과 초 (소수 3자리)
  - `v`: 속도 (m/s)
  - `alt`: 고도 (m)
- 고스트 델타, 분석 그래프에 쓴다. 비교 랩을 받을 때 큰 원본 파일 없이 이것만 받으면 된다.

### 6.9 CSV 내보내기 형식 (`export/`)

영상 오버레이 프로그램(Telemetry Overlay의 Custom CSV, RaceRender 등)에서 바로 읽고, 13.1 영상에 입히기에서도 같은 기준을 쓰기 위한 형식이다.

- **파일:** UTF-8, 쉼표 구분, 첫 줄은 열 이름. 이름은 `gachitayo_{코스이름}_{YYYYMMDD-HHmm}.csv`
- **행:** 처리된 궤적(6.7, 주행 후 스무더 결과) 기준 10Hz, 한 행에 한 시점
- **범위:** 세션 전체 또는 사용자가 고른 랩들 (앞뒤 5초 여유 포함 옵션)
- **열 (순서 고정, 단위는 열 이름에 포함):**

| 열 이름 | 내용 |
|---|---|
| `utc_time` | ISO 8601 UTC, ms까지 (예: `2026-11-12T05:31:02.300Z`). GPS 기준 절대 시각. 영상 싱크의 기준 |
| `elapsed_s` | 세션 시작부터 경과 초 |
| `lap` | 랩 번호 (출발 게이트 전은 0) |
| `lap_time_s` | 현재 랩 경과 초 |
| `sector` | 현재 구간 (1~3) |
| `distance_m` | 코스 거리 s |
| `lat`, `lon` | 도 (소수 7자리) |
| `alt_m` | 고도 |
| `speed_kmh` | 속도 |
| `heading_deg` | 진행 방향 |
| `g_lat`, `g_long` | 좌우 G(왼쪽 +), 앞뒤 G(가속 +) |
| `delta_s` | 비교 랩 대비 델타. 비교 랩이 없으면 빈칸 |
| `lap_valid` | 1 또는 0 |
| `gps_acc_m` | 수평 정확도 |

- **비교 랩:** 내보낼 때 고른다 (기본: 이 코스 내 베스트). `delta_s`는 그 기준으로 다시 계산한다.
- **랩 요약 파일:** 함께 `…_laps.csv`를 만든다. 열: `lap, lap_time_s, s1_s, s2_s, s3_s, valid, invalid_reason`
- **확장:** 나중에 OBD 같은 채널이 생기면 열을 뒤에 덧붙인다 (13.2). 기존 열의 순서와 이름은 바꾸지 않는다.

## 7. 계산 명세

모든 임계값은 `src/engine/config.ts`에 모은다.

### 7.1 지역 좌표
- 코스 원점(`origin`) 기준 평면 좌표(m)를 쓴다. 동쪽이 x, 북쪽이 y다.
- 수 km 규모의 코스라서 등장방형 근사로 충분하다.

### 7.2 거치 보정
1. **아래 방향:** 정차 상태(GPS 속도 < 0.5 m/s이고 가속도 크기 변동이 작음)에서 3초 동안 중력 벡터를 평균한다.
2. **앞 방향:**
   - 아래 방향을 구한 뒤, 직선 주행 중(요레이트가 작음)에 GPS 속도 변화율이 1.5 m/s² 이상인 구간을 찾는다.
   - 그 구간의 수평 가속 방향을 평균해서 앞 방향으로 삼는다. 부호는 속도 변화율의 부호로 정한다.
3. **왼쪽 방향:** 위 방향과 앞 방향의 외적이다. 결과 회전 행렬을 세션에 저장한다.
4. **재보정:** 중력 방향이 10° 넘게 바뀐 상태가 2초 이상 이어지면 재보정 이벤트를 남기고 1~3을 다시 한다.
   - "바뀐 상태"는 0.5초 평균 가속도와 예상 가속도(앞: GPS 속도 변화율, 왼쪽: v × 요레이트, 위: 중력)의 각도 차로 본다. 긴 제동이나 긴 코너에서 겉보기 중력이 기우는 것을 거치 변화로 착각하지 않기 위해서다.
   - 요레이트는 부호를 확인한 자이로 값을 쓴다. 자이로가 없거나 부호 확인 전에는 좌우 성분을 빼고 비교한다.
   - 직진 판단(2단계)은 자이로가 없으면 GPS 진행 방향 변화율로 한다.
   - 앞 방향을 찾기 전에 다른 정차 구간의 중력 방향이 10° 넘게 다르면(손에 들고 있다가 거치) 새 값으로 다시 시작한다.
   - 주행 중 재보정에서는 직선 등속 주행(요레이트·속도 변화가 작음) 3초도 정차처럼 아래 방향을 구하는 데 쓴다. 서킷에서는 멈출 일이 거의 없기 때문이다 (M3 결정 '나', M5에서 구현).
5. 보정이 끝나기 전에는 주행 화면에 **임시 G**(폰 센서 그대로, 모션이 없으면 GPS 추정)를 G미터의 속 빈 점으로 표시한다 (사용자 요청 "0.00이라도 G가 움직이게", "손으로 흔들어도 움직이게", 7.12). 기록(처리된 궤적·CSV)에는 넣지 않는다. 보정이 어디서 멈췄는지는 분석 화면의 "G 보정 진단"으로 본다 (주행 화면 상태 줄은 사용자 요청으로 없앰)
6. 주행 후 처리에서는 세션 전체 데이터로 보정을 다시 계산할 수 있다.
   - 재보정 지점과 정차 때 중력 방향이 바뀐 지점으로 나눈 구간마다 모든 정차 창·가속 구간을 쓴다.
7. **확인:** 보정 뒤 앞뒤 가속도가 GPS 속도 변화와 반대 방향이면 앞 방향을 뒤집는다. 코너에서 요레이트·좌우 가속도 부호를 GPS 진행 방향 변화와 비교해 플랫폼 부호를 정한다. 둘 다 끝나기 전에는 융합에 모션을 쓰지 않는다.
- 정차 구간의 평균 회전 속도는 자이로 바이어스로 쓴다.
- 직선이 없는 코스(순수 타원 등)에서는 2단계를 끝낼 수 없어 G값 없이 GPS만으로 처리된다. 실제 서킷·와인딩에는 직선 구간이 있다.

### 7.3 센서 융합
- **주행 중:** 확장 칼만 필터(EKF)를 쓴다.
  - 상태: 위치 x, y, 진행 방향 ψ, 속도 v, 앞 방향 가속도 바이어스 b
  - 예측: 50Hz로 앞 방향 가속도(ax − b)와 요레이트를 적분한다.
  - 관측: GPS 위치(분산은 `hAcc`로), GPS 속도(있으면 높은 가중치), GPS 진행 방향(v > 5 m/s일 때만)
  - 이상치: 예측 위치와 관측 위치의 거리가 3σ를 넘으면 그 GPS 점을 버린다.
    - GPS 위치 표준편차(축당) = max(1 m, hAcc × 0.5). 연속 3번 버려지면 다음 점으로 위치를 다시 맞춘다.
    - 3초 넘게 끊겼다 돌아온 첫 점은 이상치 검사 없이 받아들인다.
- **주행 후:** 같은 모델로 RTS 스무더를 돌린다 (앞에서 뒤로 필터, 뒤에서 앞으로 보정).
- **출력:** 50Hz 위치, 속도, 진행 방향
- **모션 권한이 없을 때:** GPS만으로 위치를 보간하고 GPS 속도를 쓴다. "정확도 낮음"을 표시한다.
  - GPS만으로 처리한 구간에서 GPS가 오래 끊기면, 주행 후 처리에서 끊기기 전·후의 위치와 속도로 매끄러운 곡선을 그려 잇는다.

### 7.4 GPS 준비 판정
- `hAcc` ≤ 10m인 fix가 연속 5개 들어오면 "준비 완료"로 바꾼다.

### 7.5 코스 생성

**첫 주행 자동 생성**
- 랩 코스 후보: 500m 이상 주행한 뒤, 이전에 지났던 어느 지점이든 30m 이내·진행 방향 차이 45° 이내로 다시 지난 경우 (피트에서 출발해도 된다)
  - 출발 게이트: 처음 다시 지난 곳에서 100m 안에 이전 경로와 8m 안으로 실제로 겹치는 첫 지점과 그 진행 방향 (헤어핀 옆 다리를 잘못 잇지 않게)
  - 그 첫 랩이 같은 길을 반대로 되짚은 경로(올라감 → U턴 → 내려옴)를 품거나, 앱 중단·GPS 5초 넘는 끊김에 걸치면 후보로 쓰지 않는다.
- 편도: 랩 코스 후보가 없으면 편도로 본다. 1회 주행 = 처음으로 속도가 3 m/s를 넘은 지점부터, U턴을 시작한 곳(가는 길 중 돌아오는 길과 겹치는 마지막 지점) 또는 종료 전 마지막으로 3 m/s 이상이던 지점까지.
  - 출발 게이트와 도착 게이트는 그 1회 주행의 양 끝에서 **20m씩 안쪽**에 둔다. 정차 위치가 GPS 오차 안에 있으면 다음 주행에서 출발·도착 통과가 잡히지 않기 때문이다.
  - 한 세션에서 출발 → 도착을 지날 때마다 1랩이다. 반대 방향 통과는 게이트 방향 검사로 무시한다.
- 어느 쪽이든 주행이 끝나면 사용자에게 확인을 받는다. 사용자가 다른 종류를 고르면 그 종류로 다시 만든다(랩을 골랐는데 랩 후보가 없으면 만들 수 없다고 알린다).
- 중심선: 첫 유효 랩(편도는 1회 주행)의 융합 궤적을 평활화하고 1m 간격으로 다시 샘플링한다.
  - 평활화 창의 경계는 비교로 정한다. 작은 수를 더해 넓히면 16km가 넘는 거리에서 반올림으로 사라져, 편도 끝점이 원점으로 끌려간다(2026-11-12 고침).

**지도 등록**
- 사용자가 지도에서 두 점을 탭해 출발선을 정한다. 편도면 도착선도 정한다.
- 중심선은 그 코스의 첫 주행에서 앱 중단·GPS 끊김이 없는 첫 랩으로 만든다.

**GPX 불러오기**
- `trk` 점을 쓰고, 없으면 `rte` 점을 쓴다. 평활화한 뒤 1m 간격으로 다시 샘플링한다.
  - 이 앱이 내보낸 GPX(`creator="같이타요"`)는 이미 다듬은 중심선이라 다시 평활화하지 않는다 (왕복해도 같은 코스).
  - 50m보다 짧으면 코스로 만들지 않고 알린다. 시간대 표시가 없는 시각은 UTC로 읽는다.
- 양 끝이 30m 이내면 랩 코스, 아니면 편도다. 게이트는 양 끝점과 그곳의 진행 방향으로 만든다.

**기본 코스** (사용자 요청)
- 앱에 들어 있는 코스. 사용자가 준 카카오맵 길찾기 GPX 아홉 개다:
  - 배후령 (춘천 → 화천, 8.48 km)
  - 미시령 옛길 (인제 → 고성, 10.09 km)
  - 만항재 (태백 → 만항재 쉼터, 10.69 km)
  - 말티재 (보은 장재리 → 말티재 전망대, 2.09 km)
  - 구룡령 (홍천 명개삼거리 → 양양 갈천리, 16.97 km)
  - 로코갤러리 (가평읍 복장리 → 청평면 상천리, 6.48 km. 사용자가 정한 이름)
  - 하오고개 (의왕 청계동 → 분당 운중동, 3.29 km)
  - 북악스카이웨이 (부암동 → 정릉, 7.19 km)
  - 남한산성 (성남 산성동 → 광주 남한산성면 산성리, 3.85 km)
- 경로 점은 `src/courses/builtinData.ts`에 들어 있다(위경도 소수 6자리). 처음 넣을 때만 불러오는 따로 나뉜 파일이다.
- 코스를 만드는 방법은 GPX 불러오기와 같다(평활, 1m 재샘플, 양 끝에 출발·도착선, 게이트 폭은 설정값). 모두 편도다.
- 앱을 열 때 이 폰의 코스 목록에 없으면 넣는다(처음 한 번). 나중에 추가된 기본 코스도 이렇게 들어간다.
  - 어느 기본 코스인지는 코스의 `builtin` 키로 안다. 이 키는 폰에만 두고 서버 행에는 없다.
  - 코스 번호(id)는 폰마다 새로 만든다. 서버 `courses`는 사람마다 자기 행이라, 모두가 같은 번호를 쓸 수 없다.
- 서버로 따로 올리지 않는다. 그 코스로 달린 기록을 올릴 때만, 다른 코스처럼 내 코스로 함께 올라간다(내 백업).
- 이름 바꾸기·선 옮기기·다듬기는 내 코스와 같다. 이 폰의 사본만 바뀐다.
- 기본 이름을 바꾸면(예: 가평 복장리–상천리 → 로코갤러리) 앱을 열 때 폰에 예전 기본 이름으로 있는 것만 새 이름으로 바꾼다. 사용자가 직접 바꾼 이름은 그대로.
- 코스 이름은 사용자가 정한다. 받은 파일명이 깨져 보이면 추측하지 말고 물어본다.
- 가까운 코스 자동 감지(8.3)에 똑같이 쓰인다. 멀리 있는 코스는 중심선 점을 다 보지 않는다: 첫 점까지 거리가 1km + 코스 길이보다 멀면 건너뛴다.
- 별점·후기·사용자 코스 공유는 13.5(앱 전환 뒤 계획)를 따른다.

**공통**
- 게이트 기본 폭은 30m이고 설정에서 바꿀 수 있다.
- 구간 경계는 코스 길이의 1/3과 2/3 지점이다.
- 출발선·도착선 옮기기: 게이트는 중심선 위로만 옮긴다(가장 가까운 중심선 위치에 붙임). 랩 코스는 중심선 시작을 새 출발선으로 돌리고, 편도는 출발 앞·도착 뒤를 잘라낸다. `version` +1.

**코스 다듬기 (수동 버튼)**
- 그 코스의 내 유효 랩이 3개 이상이면 쓸 수 있다.
- 중심선을 평균해서 다듬고 `version`을 +1 한다.
- 그 코스의 내 모든 랩 `trace`를 원본에서 다시 계산한다. 폰에 원본이 없으면 파일 게이트웨이를 거쳐 R2에서 받는다.

### 7.6 위치 → 코스 거리 s
- 중심선 위에서 가장 가까운 점을 찾는다. 검색 범위는 [s_prev − 20m, s_prev + max(50m, 3·v·dt)]이다. 헤어핀처럼 코스가 가까이 붙은 곳에서 튀지 않게 하기 위해서다.
- 중심선과의 횡거리가 30m를 넘으면 코스 이탈로 본다. s 갱신을 멈추고 델타를 숨긴다.
- 출발 게이트를 통과하면 s를 0으로 초기화한다.
- 출발선과 중심선 끝이 조금 어긋나 s가 먼저 넘어가면 보정한다: 랩의 절반을 달리기 전에 둘레 끝 근처로 읽히면 0, 절반을 넘게 달린 뒤 0 근처로 읽히면 둘레 끝으로 본다(넘어감으로 보는 범위는 둘레의 1/4과 50m 중 작은 쪽).
- 편도는 랩 밖(출발 전, 도착 뒤 돌아오는 길)의 s를 쓰지 않는다.

### 7.7 게이트 통과
- 연속된 두 융합 위치(50Hz)를 잇는 선분이 게이트 선분과 교차하고, 진행 방향이 게이트 방향과 같으면(내적 > 0) 통과로 본다.
- 통과 시각은 그 선분 안에서 선형 보간한다.
- 같은 게이트를 10초 안에 다시 통과하면 무시한다.

### 7.8 랩
- 랩 코스: 출발 게이트 통과부터 다음 통과까지
- 편도: 출발 게이트부터 도착 게이트까지
- 랩 번호는 완주한 순서다. 편도에서 출발했다가 도착하지 않은 주행은 번호를 쓰지 않는다(주행 중과 주행 후가 같다).
- **유효 조건 (모두 만족):**
  - s 진행이 코스 길이의 95% 이상을 덮는다.
  - 실제 이동 거리가 코스 길이 ±5% 안이다.
  - GPS가 5초 넘게 끊긴 적이 없다.
  - 코스 이탈이 없다.
- 무효면 사유를 기록한다.

### 7.9 구간 기록
- s가 구간 경계를 넘는 시각을 프레임 사이에서 보간한다.

### 7.10 이론상 베스트
- 세션 안의 유효 랩에서 구간별 최소 기록을 합한다.
- 코스 전체 기록 기준 값도 함께 계산한다.

### 7.11 델타
- 비교 랩의 `trace`에서 t_ref(s)를 선형 보간으로 구한다.
- delta = 현재 랩 경과 시간 − t_ref(s). +면 느린 것이다.
- **표시:**
  - 10Hz로 갱신한다.
  - 시간 상수 0.3초로 지수 평활한다.
  - 소수 둘째 자리까지 보여준다.
- **숨김 조건:** 코스 이탈, GPS 끊김, s 신뢰도 낮음, 비교 랩 없음. 이때는 숫자 대신 "—"를 표시한다.
- **비교 랩 기본값:** 이 코스(같은 `version`)의 내 베스트 유효 랩. 사용자가 다른 랩을 고를 수 있다.
- 비교 랩은 출발 전에 폰에 받아둔다.
- **고스트 위치 (지도 모드):** 현재 랩 경과 시간 t에서 비교 랩이 있던 코스 거리 s_ref(t)를 `trace`에서 역으로 보간해 구하고, 중심선 위 좌표로 바꿔 지도에 표시한다.

### 7.12 G값
- 차 기준 `ax`, `ay`를 0.2초 이동평균한다. 값이 없는 칸(보정 전, 모션 끊김)은 빼고 평균한다.
- g 단위(9.80665 m/s²)로 표시한다.
- **보정 전 임시 G (주행 화면만, 사용자 요청 "흔들어도 움직이게"):** 부호까지 확인된 보정이 끝나기 전에는 G미터의 점을 속 빈 원으로 표시하고 기록에는 넣지 않는다. 보정이 끝나면 바로 정식 G로 바뀐다.
  - **폰 센서 그대로 (모션이 있을 때):** 손으로 흔들어도 바로 움직인다.
    - 위 방향: 보정기가 정차로 잡은 위 방향이 있으면 그것, 없으면 가속도의 3초 저역 통과(중력). GPS로 보아 가감속·코너 중(0.5 m/s² 넘음)이면 저역 통과를 멈춘다.
    - 앞 방향: 보정기가 앞 방향까지 잡았으면(부호 확인 전) 그것. 아니면 "화면이 운전석 쪽을 보게 거치"로 가정해 화면 뒤쪽의 수평 방향, 폰이 거의 누워 있으면 폰 위쪽을 앞으로 본다. 왼쪽 = 위 × 앞.
    - 가정한 방향은 거치 방향이나 기기(아이폰 가속도 부호)에 따라 거꾸로일 수 있어서, 아래 GPS 추정 G와 부호를 계속 비교해 0.8 m/s² 넘는 표본이 1초 넘게 쌓이면 앞뒤·좌우 부호를 따로 맞춘다. 폰을 비스듬히 거치하면 앞뒤·좌우가 섞일 수 있다.
  - **GPS 추정 (모션이 없을 때, 그리고 위 부호 맞추기용):** 융합한 속도와 진행 방향의 1초 변화로 앞뒤(속도 변화율)·좌우(속도 × 진행 방향 변화율). 2 m/s보다 느리면 좌우는 0, ±12 m/s²에서 자른다. GPS 1 Hz라 0.5~1초 늦고, 모의 주행에서 정답 대비 RMS 앞뒤 0.21 g·좌우 0.24 g (늦음을 빼면 0.08·0.14 g).

### 7.13 고도
- GPS 고도에서 `altAcc`가 큰 점을 빼고 평활화한다.
- 참고용이다. 폰 GPS 고도는 수평 위치보다 오차가 크다.

  - 터치 영역은 44px 이상

### 8.1 첫 실행
1. 닉네임 입력 (익명 계정 생성). 서버 주소가 아직 없을 때 첫 실행을 마쳤으면, 서버가 생긴 뒤 앱을 열 때 저장된 닉네임으로 계정을 조용히 만든다(통신이 없으면 다음 기회에). 이때는 "계정 끊김" 경고를 보이지 않는다 (M6 결정)
2. 위치와 모션 권한 안내. 아이폰은 버튼을 탭해야 허용 창이 뜬다.
3. 홈 화면 추가 안내
   - 아이폰: 공유 → 홈 화면에 추가
   - 안드로이드: 메뉴 → 앱 설치
4. 안전 안내 확인: "공도에서는 교통법규를 지키고, 주행 중에는 앱을 조작하지 마세요."

### 8.2 메인 화면 (통합)

앱을 열면 나오는 화면이다. 화면 맨 아래에 탭 4개를 둔다: **메인 / 코스(8.7) / 기록(세션 목록 → 8.6 분석) / 설정(8.8)**.
- 아래 탭은 화면 맨 아래에 붙는다. 아이폰 홈 화면 앱에서 일부 iOS 버전이 화면 높이(100dvh)와 화면 고정(fixed) 요소를 상태 표시줄만큼 작게 잡아 아래가 비거나 잘리는 문제가 있어, 홈 화면 앱일 때는 화면 크기로 앱 높이를 정하고, 문서는 스크롤하지 않게 고정(스크롤은 앱 안에서)하며, 화면 전체를 덮는 요소(주행 화면, 고르기 창, 안내 창)는 fixed 대신 문서 맨 위에 붙여 그린다 (사용자 요청)

**배치 (사용자 요청):** 지도가 화면 전체이고, 위쪽 카드와 아래 탭은 반투명으로 지도 위에 얹는다. 내 위치·화면 맞추기는 **얹은 칸에 가려지지 않은 영역** 기준이다 (내 위치는 위 카드 아래 ~ 탭 위 사이의 정가운데, 화면 정가운데가 아님). GPS 상태는 지도 오른쪽 위 아이콘의 색(초록 오차 10 m 안 · 노랑 30 m 안 · 빨강 그보다 큼이나 권한 없음 · 회색 위치 없음). 이 GPS 아이콘을 누르면 내 위치로 간다(따로 있던 오른쪽 아래 "내 위치" 버튼은 없앰, 사용자 요청). 위치 공유는 왼쪽 위, 지도 출처는 탭 바로 위 오른쪽. 위치를 못 잡았을 때 "위치를 받으면 지도에 표시돼요" 같은 안내 말풍선은 띄우지 않는다 (사용자 요청).

**주행 전 상태**
- **위쪽 카드 (지도 위에 얹음):**
  - (앱 이름·설정 버튼 머리글은 없앰, 사용자 요청. 설정은 아래 탭)
  - 감지된 코스 카드: "현재 위치에서 감지됨", 코스 이름, 종류·길이·내 베스트. 근처에 코스가 없으면 한 줄짜리 작은 카드 "새 코스 · 근처 코스 없음" (위치 권한이 없을 때만 안내 한 줄 더, 사용자 요청). GPS 오차 글자는 빼고 지도의 GPS 아이콘 색으로 (사용자 요청).
  - 업로드 대기가 있으면 한 줄로 표시 (작게). 계정이 끊겼으면 경고 한 줄 (9장)
  - 큰 "주행 시작" 버튼 → 8.3 주행 준비
- **지도 (화면 전체, 위 카드·아래 탭 아래에 깔림):**
  - 통신이 되면 OSM 타일 위에, 안 되면 타일 없이 격자 위에 그린다. 타일이 연달아 6번 실패해도 통신이 없는 것으로 보고 타일을 뺀다. 타일은 어두운 화면에 맞게 색을 뒤집어 어둡게 보여준다 (M7)
  - 내 위치(정확도 원), 코스 선, 출발선(편도면 도착선). 코스가 바뀌거나 처음 위치를 받으면 화면을 맞추고, 사용자가 지도를 옮긴 뒤에는 위치가 바뀌어도 그대로 둔다 (M7)
  - 지도 라이브러리(Leaflet)는 메인 화면이 처음 열릴 때 따로 불러온다. 서비스 워커가 함께 보관해 통신 없이도 열린다. 타일은 서비스 워커가 보관하지 않는다 (OSM 이용 정책) (M7)
  - 내 위치로 가기: 오른쪽 위 GPS 아이콘(누르는 영역 46px)을 누른다. 내 위치로 옮기고 다시 따라간다. 아이콘 색은 그대로 GPS 상태(약하면 빨강). 코스가 없으면 내 위치를 따라가다가, 사용자가 지도를 옮기면 멈춘다 (사용자 요청)
  - 오른쪽 아래에 지도 출처("© OpenStreetMap"). 버전·빌드 시각은 지도에 두지 않고 설정(8.8)에만 둔다 (사용자 요청)
  - 왼쪽 위 "위치 공유 꺼짐/위치 공유 중" 버튼 (서버 계정이 있을 때, M8):
    - 켤 때 "친구 N명에게 내 위치가 보여요"라고 확인을 받는다. 친구가 없으면 설정의 친구로 안내한다.
    - 켜 있는 동안 앱이 화면에 보이면 5초마다 내 위치를 보낸다(어느 탭에 있어도, 주행 중에도). 위치가 30초 넘게 안 들어오면 보내지 않는다. 끄면 서버에서 지운다.
    - 공유는 앱을 다시 열면 늘 꺼져 있다 (깜빡 켜 둔 채로 위치가 나가지 않게).
  - 위치 공유 중인 친구 점(파랑)과 닉네임: 메인 화면이 보이는 동안 5초마다 받아 온다. 30초 넘게 지난 위치는 흐리게.
  - 왼쪽 아래 "위치 공유 중인 친구 N명": 누르면 친구들과 내가 다 보이게 지도를 옮긴다 (GPS 아이콘을 누르면 다시 따라간다)
  - (3단계) "같이 달리기" 버튼

**주행 중 상태** = 8.4의 지도 모드

### 8.3 주행 준비
- "주행 시작"을 누르면 권한을 확인하고 센서 기록을 시작한 뒤 이 화면으로 온다. GPS 준비와 거치 보정을 미리 하고, 이때의 정차 구간은 주행 후 처리의 거치 보정에도 쓰인다. 여기서 취소하면 그 기록은 지운다.
- **배치 (사용자 요청):** 맨 위에 "기록 시작" 버튼과 안내, 그 아래 준비 상태(GPS·모션 센서·거치 보정), 위치 공유(친구가 있을 때), 그다음 코스·비교 랩·화면 모드·지도 보기·앞 친구 간격·상단 표시 값.
- **주행 중 위치 공유 (사용자 요청):** 켜기/끄기. 켤 때 메인 지도와 같은 확인 창("친구 n명에게 내 위치가 보여요. 주행 중에도 계속 보내고…"). 기록 시작 전에 켜야 친구의 앞 친구 간격(실시간 방)에도 내 위치가 간다.
- **코스 선택:** 현재 위치로 자동 감지(가까운 코스 게이트 기준), "변경"으로 목록에서 선택, 또는 새 코스
- **비교 랩 선택:** 기본은 내 베스트(랩타임·날짜·랩 번호). "변경"으로 다른 랩을 고른다.
- **화면 모드 선택:** 지도 / 미니멀 / 대시보드. 기본은 설정의 기본 모드(처음에는 지도). "주행 중 두 번 탭하면 다음 모드"
- **상단 표시 값:** 현재 선택("델타 + G미터 · 속도")을 보여주고, 누르면 8.3.1로 이동
- **GPS 상태:** "GPS 대기 중"에서 "준비 완료 · 오차 n m"로 바뀌는 것을 보여준다.
- **모션 센서:** 허용됨 / 거부됨(거부면 G값 없이 진행)
- **거치 보정:** "3초간 정차해 주세요" 안내와 진행 표시. GPS로는 3초 멈췄는데 보정기가 아직 받아들이지 않았으면(폰 흔들림·GPS 점 부족 등) "0초 남음" 대신 "확인 중 · 폰이 흔들리지 않게 거치대에 둔 채 잠시 더 기다려 주세요"
- **거치 팁 링크:**
  - 하늘이 잘 보이는 앞유리 쪽에 거치한다.
  - 금속 성분 썬팅을 피한다.
  - L1+L5 이중 주파수 GPS를 지원하는 폰이 유리하다.
- **앞 친구 간격 (선택, M9):** 서버 계정과 친구가 있을 때만 보인다.
  - 친구 칩에서 앞 친구를 고르거나 "끄기". 위치를 공유 중인 친구는 파란 점으로 표시한다.
  - 목표 간격: −/+로 0.5초씩, 1~10초 (기본 2초). 고른 친구와 목표는 폰에 저장해 다음 주행에도 쓴다. 친구를 끊으면 지운다.
  - 처음 켤 때 한 번 안전 안내: "간격은 참고용이에요. 주행 중에는 화면 대신 도로를 보세요. 공도에서는 교통법규와 안전거리를 지키세요. 목표 간격은 1초 이상만 정할 수 있어요."
  - 앞 친구가 메인 지도에서 위치 공유를 켜고 주행해야 간격이 보인다고 안내한다.
- **"기록 시작" 버튼**(맨 위)과 안내: "출발선을 지나면 랩 측정이 시작됩니다", "주행 중에는 화면을 조작하지 마세요"

### 8.3.1 상단 표시 값 선택
- 미리보기: 델타(고정) + 칸 1 + 칸 2
- 칸마다 고를 수 있는 값: G미터, 속도, 현재 랩타임, 구간 기록(현재 구간 델타), 최고 속도, 랩 번호, 앞 친구 간격(지금 간격 초, M9)
  - (13.2 이후) RPM 등 OBD 값이 목록에 추가된다.
- 한 칸에서 다른 칸의 값을 고르면 두 칸이 서로 바뀐다.
- 선택은 폰에 저장하고 다음 주행에도 쓴다. 기본값: G미터, 속도

### 8.4 주행 화면

**지도 모드 (기본, 주행 중 메인 화면)**
- **배치 (사용자 요청):** 지도가 화면 전체이고, 델타·고른 값 2칸(위)과 "길게 눌러 종료"(아래)는 반투명으로 얹는다. 내 위치는 **게이지 아래 ~ 종료 버튼 위 사이의 정가운데** (나를 가운데·진행 방향 위 보기, 전체 코스 보기도 그 영역에 맞춘다). 진행 방향 위로 돌리는 지도판은 그 자리를 중심으로 돌려도 화면 네 모서리를 다 덮는 크기. 가로 화면(높이 520 px 이하)은 예전처럼 값과 지도를 옆에 나란히.
- **위 (지도 위에 얹음):**
  - 델타: 크게, 빨강/초록 + "베스트 대비 · 빠름/느림" 글자. 앞 친구를 골랐으면 **친구와의 델타**이고 제목은 **"Delta (친구이름)"** (사용자 요청, 아래 앞 친구 간격)
  - 랩 번호와 현재 랩 경과 (작게)
  - 고른 값 2칸 (8.3.1)
- **하단 2/3 지도:**
  - OSM 바탕 지도(어둡게) 위에 그린다: 코스 선, 출발선(편도면 도착선), 내 위치(진행 방향 화살표), 베스트 고스트 위치(점선 원. 비교 랩에서 지금과 같은 경과 시간에 있던 위치, 7.11). 설정 "주행 중 바탕 지도"를 끄거나, 통신이 없거나 타일이 연달아 실패하면 타일 없이 그린다 (사용자 요청 "지도 안 뜸"). 바탕 지도가 있을 때 나를 가운데·진행 방향 위 보기는 확대 17단계(폰 너비로 약 370 m)로 고정한다.
  - 보기 세 가지 (사용자 요청, 주행 준비·설정에서 고르고, 주행·재생 중에는 지도 **왼쪽 위 나침반 버튼**을 누를 때마다 전체 코스 → 나를 가운데 → 진행 방향 위로 바꾼다. 버튼 옆에 지금 보기 이름, 바늘은 화면에서 북쪽(진행 방향 위에서는 지도와 같이 돈다). 바꾼 보기는 설정에 저장한다. 이 버튼은 두 번 탭으로 치지 않는다. 지도 출처 표시는 오른쪽 위):
    - **전체 코스** (기본): 코스 전체가 한 화면에 보이게 고정한다 (북쪽이 위, 좌우 여백 28 px).
    - **나를 가운데:** 내 위치를 아래 띠를 뺀 화면 가운데에 고정, 북쪽이 위. 화면 너비에 보이는 거리는 60 km/h까지 300 m, 160 km/h에서 800 m로 속도에 따라 천천히 바뀐다.
    - **진행 방향 위:** 나를 가운데에 두고 내비처럼 진행 방향이 늘 위가 되게 지도를 돌린다(진행 방향은 부드럽게). 북쪽은 나침반 버튼 바늘로 보여준다.
  - **공유 중인 친구들 (사용자 요청 "주행 중에도 위치 공유"):** 주행 중(재생 제외) 5초마다 친구 위치를 받아 보라 점과 닉네임으로 그린다. 설정·주행 준비의 "주행 지도에 친구 위치: 보이기/끄기"로 끌 수 있고, 끄면 받아 오지도 않는다 (사용자 요청). 앞 친구 간격으로 고른 친구는 실시간 방의 위치로 따로 그리므로 뺀다. 친구가 2분 넘게 안 보내면 서버가 빼서 사라진다.
  - 위치 계산은 10 Hz지만 **지도는 화면 주사율(최대 60 Hz)로 따로 그린다** (사용자 요청 "지도가 뚝뚝 끊긴다", `ui/components/LiveMap.tsx`): 받은 위치 사이를 시간에 비례해 이어(0.1초 늦게, 다음 위치가 늦으면 반 칸까지 늘림) 내 화살표·앞 친구·고스트·지도판이 매 프레임 조금씩 움직인다. 진행 방향 위 보기의 회전과 나를 가운데 보기의 보이는 거리도 매 프레임 부드럽게 바꾼다. 바탕 지도는 매 프레임 다시 맞추지 않고 그만큼만 민다(크게 떨어지면 한 번 맞춤). 위쪽 숫자 칸은 10 Hz 그대로. 브라우저 측정: 지도 그림이 1초에 47번 바뀜(예전 10번).
  - 코스 중심선이 아직 없으면(지도로 등록하고 첫 주행 전) 출발선과 내 위치만 그린다.
  - 델타·속도·G·미니맵은 `ui/overlay/`의 "시각 t의 상태 → 캔버스 그리기" 함수로 그린다 (5.1의 12번, 13.1 확장 지점).
  - 앞 친구 간격을 켰으면 앞 친구를 보라 점과 닉네임으로 그린다 (M9). **위치는 받은 마지막 위치가 아니라 "지금 있을 위치"를 예측한다** (사용자 요청 "부드럽게, 일정 속도로 가면 도로를 따라", `engine/live/friendMotion.ts`): 받은 마지막 위치(튄 점 빼고)에서 그 GPS 속도로 계속 간다고 보고, 코스 선이 있으면 그 선을 따라 거리만큼, 없으면 최근 세 점의 방향 변화율로 휘어지며(일정 속도·일정 회전, 3초까지) 나아간다. 시각은 내 위치와 같은 GPS 기준이라 지도에서 둘의 거리가 맞다. 새 위치가 와서 예측이 바뀌면 그 차이를 0.6초 동안 서서히 줄여 아이콘이 튀지 않는다(60 m 넘게 차이 나면 바로 옮김). 시뮬에서 실제 친구 위치와의 차이: 받은 마지막 위치를 쓰면 평균 21 m(최대 41 m), 예측하면 평균 6 m(최대 20 m)
  - (3단계) 같이 달리는 친구 여러 명의 점과 "닉네임 앞/뒤 N초" 라벨, "같이 달리는 중 N명"
- **아래 상태 줄은 없앤다 (사용자 요청):** "GPS 약함 · 코스 기록 중 · G 없음 · 코스 이탈 · 앞 친구 신호 없음 · 두 번 탭하면…" 글자를 모두 뺀다. GPS는 지도 오른쪽 위(나침반 버튼과 마주 보는 자리) 아이콘의 색으로만: 초록 준비 완료 · 노랑 준비 전 · 빨강 약함·끊김(3초 넘게 안 옴) · 회색 없음. 미니멀·대시보드는 종료 버튼 위 오른쪽에 같은 아이콘. "길게 눌러 종료"는 화면 맨 아래(홈 표시줄 바로 위). 지도 출처는 종료 버튼 바로 위 오른쪽

**앞 친구 간격 (M9, 주행 준비에서 앞 친구를 골랐을 때)**
- 모든 모드의 큰 델타 자리에 "지금 간격 − 목표 간격"을 소수 첫째 자리로 보여준다. 목표보다 0.2초 넘게 가까우면 빨강(느림 색) "가까움", 0.2초 넘게 멀면 초록(빠름 색) "멂", 그 사이는 "유지". 제목은 "Delta (지훈)" (사용자 요청, 예전 "앞 지훈 · 목표 2.0초").
- 지도 모드 패널 오른쪽: 작게 "목표 2.0초", 크게 지금 간격 "2.6초". 내 기록 델타(베스트 대비)는 보이지 않는다 (사용자 요청: 델타 칸은 친구와의 델타). 앞 친구를 안 골랐으면 지금처럼 베스트 대비 델타.
- 간격 = 앞 친구가 지금 내 자리를 몇 초 전에 지났는지 (`engine/live/gap.ts`). 시각은 두 폰 모두 GPS 기준(내 위치는 융합 시각 + tFix−tRecv 중앙값)이라 통신이 늦어도 값이 밀리지 않는다.
  0. **친구 위치가 아직 내 자리까지 안 왔으면** (간격이 짧거나 친구 위치가 늦게 옴, 사용자 문의 "델타 딜레이"로 고침): 친구의 최신 점(튄 점이면 그 앞 점, 최근 3개까지)을 **내가 지난 시각**을 내 최근 30초 경로에서 찾아 "내가 지난 시각 − 친구가 지난 시각" (그 점에서의 간격). 그 점 앞뒤 0.5초로 내 방향·속도를 잡아 시각을 맞춘다. 직선으로 늘려 짐작하지 않아 코너에서도 맞다.
     - **지금으로 옮기기 (사용자 요청 "최대한 예민하게"):** 친구가 그 점 뒤에도 그때의 속도 비율(내 속도 ÷ 친구 GPS 속도, 0.71~1.4로 자름)로 같은 길을 달린다고 보고, 내가 그 점에서 지금 자리까지 온 시간을 친구 시간으로 바꿔 뺀다. 친구가 나보다 느리면 간격이 바로 줄고, 빠르면 바로 는다. 친구 GPS 속도가 없거나 3 m/s보다 느리면 같은 속도로 본다.
  1. 내 경로가 아직 없으면(주행 시작 직후): 친구 마지막 구간을 그 속도로 1.5구간까지 늘려 계산.
  2. 그 밖에는 친구가 보낸 최근 3분 위치를 잇고, 같은 방향(60° 안)으로 옆 25 m 안을 가장 최근에 지난 시각. 친구 최근 위치가 300 m 안인데 20초 넘게 전 통과를 고르면 한 바퀴 전 기록이라 버린다.
  - 튄 점: 주변 점 두 개로 예상한 자리(앞뒤 사이, 앞의 두 점으로 늘림 등) 어느 것과도 30 m 넘게 어긋나면 튄 점. 튄 점과 이은 방향은 쓰지 않는다.
  - 화면 값은 0.15초 시간 상수로만 부드럽게 한다 (사용자 요청 "최대한 예민하게": 1초 → 0.5초 → 0.15초).
  - **시뮬 실측 (실제 주행 화면 부품, 친구 위치 1초마다 0.8초 늦게, 내 GPS 0.5초 늦음):** 실제 대비 오차 RMS 0.10초(최대 0.25초), 따라오는 지연 약 0.3초.
  - **모의 주행 실측 (서킷, GPS 1 Hz·잡음 3 m·튄 점 1%, 내 위치 잡음 2 m):** 간격 1·2·5초, 친구 위치가 0~2.5초 늦게 와도 오차 RMS 0.11~0.17초, 0.5초 넘게 틀리는 때 1% 미만, 값이 늘 나온다. 고치기 전에는 간격 1초·1.5초 늦게 올 때 코너에서 한 바퀴 전 기록과 헷갈려 최대 43초 틀렸다.
  - **화면 지연:** 통신 지연은 값에 안 들어간다(시각으로 계산). 화면 값은 내 GPS가 늦은 만큼(폰마다 0.2~1초)과 부드럽게 하는 0.4초만큼 늦다. 간격이 친구 위치 지연보다 짧으면 그만큼(1~2초) 지난 자리의 값이다. 실제 두 폰 지연은 실측으로 확인한다.
- 앞 친구 위치가 5초 넘게 안 오면 제목이 "Delta (지훈) · 신호 없음", 값은 —.
- 재생 모드에서는 쓰지 않는다 (가상 친구 따라가기만 예외, 10.2).

**미니멀 모드**
- 화면 가운데 큰 델타 (예: `+0.42` 빨강, `−0.31` 초록)와 "비교 2:04.318 · 내 베스트"
- 작게 현재 랩타임과 랩 번호
- 랩을 통과하면 그 랩타임을 3초간 크게 표시한다("랩 3 완료 2:03.871"). 비교 랩보다 빠르면 "새 베스트 −0.447"도 함께 보인다.

**대시보드 모드**
- 델타, 속도, G미터(원 안에서 움직이는 점과 좌우·가감속 값)
- **G미터 (사용자 요청):** 글자("G", "추정", "좌 0.00 · 제동 0.00", 원 둘레의 "제동"·"좌")는 지우고 원을 칸 안에서 가장 크게 그린다 (지도 모드 G 칸·대시보드 G 칸). 보정 전 임시 G는 점을 속 빈 원으로 구분한다. 화면 읽기 프로그램용 이름에는 값과 "추정"을 넣는다. 바깥 원 = 설정의 최대값(1.5 / 2 / 2.5 / 3 g, 기본 2 g), 원 안 오른쪽 위에 그 값만 작게. 눈금 원은 1.5 g면 0.5 g마다, 그 위는 1 g마다. 최대값 밖의 G는 바깥 원 둘레에 붙인다. 최근 2초의 G를 궤적으로 그린다: 3점 이동평균으로 튀는 값을 누그러뜨리고 캣멀롬 곡선(베지어)으로 매끈하게, 오래된 것부터 옅게. 지도 모드 G 칸·대시보드·분석 G 다이어그램(최대값만)이 같은 설정을 쓴다.
- 랩 번호, 현재 랩, 베스트 랩
- 구간 3칸: 구간 기록과 비교 랩 대비 구간 델타. 지금 달리는 구간을 표시하고, 아직 안 간 구간은 "—"

**공통**
- 화면을 두 번 탭하면 모드가 지도 → 미니멀 → 대시보드 → 지도 순서로 바뀐다.
- "종료"는 1초 길게 눌러야 동작한다 (사용자 요청으로 2초에서 줄임). 그 밖의 터치는 무시한다.
- 가로와 세로를 모두 지원한다.
- 화면 꺼짐 방지를 켠다. 화면이 다시 보이면(`visibilitychange`) 다시 요청한다.
- 상태 표시: GPS 아이콘 색만 (글자 상태 표시는 사용자 요청으로 없앰)
- 지도 모드는 설정 "주행 중 바탕 지도"(기본 켬)에 따라 지도 타일을 불러온다. 끄면 코스 선과 점만 그린다 (발열·배터리·데이터 부담 감소). 미니멀과 대시보드에서는 지도를 그리지 않는다.

**첫 주행 (코스 없음)**
- 속도와 출발 뒤 경과 시간만 표시하고 "코스 기록 중"을 띄운다. 랩은 주행이 끝난 뒤 계산한다. 지도 모드면 지나온 경로를 그린다.

**비교 랩 없음 (코스는 있음)**
- 랩타임과 구간 기록은 보여주고, 델타 자리에는 "—"를 표시한다.

### 8.5 주행 종료 요약
- 종료하면 폰에서 주행 후 처리(5.4)를 돌린 뒤 이 화면을 보여준다. 처리 중에는 진행 표시.
- "오늘 · 코스 이름 · n랩"
- 베스트 랩을 크게(강조색). 개인 기록을 갱신했으면 "개인 기록 갱신 −0.447"
- 이론상 베스트, 유효 랩 수(예: 7/8)
- 랩 표: 랩, 시간, 베스트 대비. 베스트 행을 강조하고, 무효 랩은 취소선과 사유("무효 · GPS 끊김")
- 첫 주행이면 "새 코스로 저장할까요?":
  - 감지 결과 설명(예: "출발점으로 돌아와서 랩 코스로 감지했어요")
  - 랩 코스 / 편도 구간 선택 (바꾸면 그 종류로 다시 만든다, 7.5)
  - 코스 이름 입력, 저장. 편도면 작은 지도로 출발·도착 위치를 보여준다.
  - 저장하지 않으면 코스 없이 주행 기록만 남는다.
- 업로드 상태 한 줄
- "홈으로", "분석 보기" (분석 화면이 생기면)

### 8.6 분석

**기록 지우기 (M10, 사용자 요청):** 기록 탭 목록의 각 줄 오른쪽 휴지통 → 확인 창("폰과 서버에서 모두 지워요. 되돌릴 수 없어요") → 지우기.
- 폰: 세션, 원본 덩어리, 처리 결과, 비교 랩을 지운다. 그 랩이 비교 랩(베스트)이었으면 다음으로 빠른 랩이 비교 랩이 된다. 코스는 남는다.
- 서버: 올리기 대기를 빼고 "서버에서 지우기"를 대기열에 넣는다. 통신이 없으면 연결될 때 지운다(재시도 간격은 올리기와 같음).
- 기록 중인 주행은 지울 수 없다.

- **들어가기:** 기록 탭의 계산된 기록을 누르거나, 종료 요약의 "분석 보기" (M10)
- **랩 목록:** 랩타임, 구간 기록, 베스트·무효 표시, 이론상 베스트. 랩을 누르면 그 랩이 A (기본은 베스트)
- **두 랩 비교 (같은 세션 또는 같은 코스의 다른 세션):**
  - 속도, 델타, 고도 그래프. 가로축은 코스 거리다. 그래프는 uPlot(이 화면을 열 때 따로 불러옴). 델타는 A − B(A가 느리면 +)
  - 비교 랩 B: 이 주행의 다른 랩 또는 같은 코스·버전의 다른 주행 랩(빠른 순 8개). 기본은 다른 주행의 베스트, 없으면 이 주행의 다음으로 빠른 랩 (M10)
  - 속도 색칠 지도에 두 랩의 주행 라인을 함께 표시한다: 랩 A는 속도 색(느림 파랑 → 빠름 빨강), 랩 B는 회색 점선(다른 주행이면 그 주행 결과가 폰에 있을 때). OSM 지도(어둡게), 끌기·확대 가능 (M10)
  - G 다이어그램 (좌우 G와 앞뒤 G)
- **지점 정보:** 그래프 위 한 지점을 누르면 지도에 그 위치가 표시되고, 위도·경도·고도·속도·시간이 뜬다. 지도에서 눌러도 같은 동작을 한다.
- **데이터 출처:** 그래프는 `trace`를, 지도·지점 정보·G 다이어그램은 처리된 궤적 파일을 쓴다.
- **상단 버튼:**
  - "내보내기": CSV(6.9), 랩 요약 CSV, GPX. CSV 범위는 세션 전체 / 랩 A만(앞뒤 5초), 델타의 비교 랩은 화면에서 고른 B. GPX는 원본 GPS 점(원본이 정리됐으면 처리된 궤적). 아이폰은 공유 창, 그 밖은 다운로드 (M10)
  - "영상에 입히기": 13.1이 구현되기 전에는 숨긴다.
- **G 보정 진단 (실차 도구, 사용자 문의 "G가 기록 안 됨"):** 분석 화면 맨 아래 "G 보정 진단 → 보기". 원본으로 보정기(7.2)를 그대로 돌려 어느 단계에서 멈췄는지, 동작 센서(초당 횟수, 0.2초 넘게 끊긴 횟수, 자이로 유무), GPS(간격, 속도 값 없는 비율), 정차 3초 창이 막힌 이유(GPS 점 부족 / 센서 끊김 / 흔들림 큼, 가장 작은 흔들림), 직진 가감속 후보(0.15g 이상 횟수와 막힌 이유 회전 중 / 센서 끊김, 0.10~0.15g 횟수, 가장 센 가감속)를 한 화면에 보여준다. 캡처해서 보내면 원인을 찾을 수 있게 숫자를 다 넣는다.

### 8.7 코스 관리
- 코스 목록: 이름, 종류·길이, 내 베스트. 누르면 코스 상세. 위에 "지도에서 새 코스"·"GPX 불러오기" (M10)
  - "내 코스"와 "기본 코스"(7.5)로 나눈다.
  - 기본 코스는 정한 순서(받은 순서: 배후령 · 미시령 옛길 · 만항재 · 말티재 · 구룡령 · 로코갤러리 · 하오고개 · 북악스카이웨이 · 남한산성)로 보이고, 어디서 어디로(예: 춘천 → 화천)를 같이 보인다.
  - 내 코스가 없으면 "주행을 시작하면 첫 주행으로 내 코스를 만들어요." 한 줄.
  - 코스를 고르는 다른 목록(주행 준비)도 내 코스 먼저, 그다음 기본 코스다.
  - 코스 상세의 출처 칸은 "기본 코스"다.
- 코스 상세 (M10):
  - 지도(OSM): 중심선, 출발선(편도면 도착선, 점선), 구간 경계(1|2, 2|3 점)
  - 코스 그리기 (사용자 요청 시안 2, 코스 상세·메인·새 코스 지도. 주행 지도는 빨강이 "느림" 색이라 그대로):
    - 코스 선: 빨간 선 + 빛 번짐(넓고 옅은 빨강 두 줄 + 진한 빨강 + 가운데 밝은 줄)
    - 출발: 파랑 핀(끝이 출발선 가운데) + 위에 큰 파랑 글자 "출발". 출발선도 파랑
    - 도착: 빨강 핀 + 위에 큰 빨강 글자 "도착". 도착선은 흰 점선
    - 구간 경계: 큰 노랑 점 + 위에 노랑 글자 (1|2, 2|3)
    - 글자는 17px 굵게, 검은 테두리. 화면 맞출 때 핀·글자 높이만큼 위를 더 비운다
  - 이름 바꾸기 (서버에도 올린다: 대기열 종류 `course`)
  - 출발선·도착선 옮기기: 버튼 → 지도에서 누르기 → 확인 창. 중심선 위 가장 가까운 곳으로 붙고, version +1, 이 코스의 내 기록을 모두 원본에서 다시 계산한다(질문 5 결정). 폰에서 원본을 정리한 기록은 서버에서 원본을 받아 다시 계산하고, 받지 못하면 건너뛰고 몇 개인지 알린다. 중심선이 없는 코스(지도로 만들고 첫 주행 전)는 옮길 수 없다.
  - 코스 다듬기: 같은 버전의 유효 랩이 3개 이상이면. 랩 경로를 평균해 중심선을 다시 만들고 version +1, 다시 계산
  - GPX 내보내기 (중심선, 없으면 출발·도착 두 점)
  - "이 코스로 주행" (사용자 요청): 주행 준비를 열고 이 코스를 고른다("직접 고름"). 위치로 자동 감지한 코스가 덮어쓰지 않는다. 이미 기록 중이면 준비 화면으로만 간다.
  - 역방향 코스 (사용자 요청): 같은 길을 반대로 달리는 코스를 내 코스로 만든다(이름 "○○ 역방향", 버전 1). 원래 코스와 그 기록은 그대로, 기록은 방향마다 따로 쌓인다.
    - 편도: 출발·도착을 맞바꾸고 선의 진행 방향도 뒤집는다. 랩: 출발선 자리는 그대로, 방향만 반대.
    - 기본 코스도 된다. 이미 같은 코스(종류가 같고 출발선·도착선이 30 m 안, 방향 60° 안)가 있으면 새로 만들지 않고 그 코스로 간다 (역방향의 역방향 = 원래 코스).
  - 내비로 가기 (사용자 요청): 출발점·도착점(랩 코스는 "출발·도착점" 한 줄)마다 "네이버 지도"·"카카오맵" 버튼. 목적지는 출발선·도착선 가운데.
    - 네이버 지도: `nmap://navigation?dlat=&dlng=&dname=&appname=`으로 바로 길안내. `appname`은 이 웹페이지 주소.
    - 카카오: 카카오내비를 바로 여는 공식 방법은 카카오 개발자 앱 키(JavaScript SDK `Kakao.Navi.start`)가 있어야 한다. 그래서 지금은 키 없이 되는 카카오맵 자동차 길찾기(`kakaomap://route?ep=위도,경도&by=CAR`)로 연다. 카카오맵에서 "안내 시작"을 누르면 길안내. 앱 키를 받으면 카카오내비 바로 열기로 바꿀 수 있다.
    - 안드로이드는 `intent://`로 연다. 앱이 없으면 크롬이 네이버는 플레이 스토어, 카카오는 웹 길찾기(`https://map.kakao.com/link/to/이름,위도,경도`)로 보낸다. 아래에 앱 설치 링크(아이폰은 앱 스토어)를 둔다.
  - 코스 지우기 (사용자 요청): 내 코스만. 기본 코스(7.5)는 버튼이 없다.
    - 확인 창에 함께 지워질 기록 수를 보인다: "○○ 코스와 이 코스로 달린 기록 N개를 폰과 서버에서 모두 지워요. 되돌릴 수 없어요."
    - 이 코스로 달린 기록을 모두 지운다(기록 지우기와 같은 방법, 서버에서도). 그다음 코스와 비교 랩을 지운다. 기록을 남기지 않는 이유: 코스 없는 기록을 다시 계산하면 새 코스를 만들려고 한다.
    - 서버: 대기열 `course-delete`로 `DELETE /api/courses/{id}`. 기록 지우기 뒤에 넣는다. 서버에 이 코스의 기록이 남아 있으면 409로 거절하고 나중에 다시 한다.
    - 기록 중인 코스는 지울 수 없다. 주행 준비에서 고른 코스였으면 코스 없이로 돌아간다.
- 지도에서 새 코스 (M10): 이름, 종류(랩/편도), 지도에서 출발선 위치 → 진행 방향 점을 차례로 누른다(편도는 도착선도). 게이트 폭은 설정값. 중심선은 첫 주행 뒤 생긴다(7.5).
- GPX 불러오기 (코스로 등록, 게이트 폭은 설정값)
- GPX 내보내기 (코스 또는 세션: 세션은 분석 화면 내보내기)
- 시간 정보가 있는 GPX를 불러오면 "코스로 등록"과 "주행 기록으로 가져오기" 중에서 고른다.
  - 주행 기록으로 가져오면 모션 데이터 없이 GPS만 있는 세션으로 저장하고 바로 계산한다(종료 요약으로 이동).
  - 속도는 GPX 확장 영역(예: 가민 TrackPointExtension)에 값이 있으면 그 값을 쓰고, 없으면 위치와 시간으로 계산한다.

### 8.8 설정
- 닉네임
- 친구 (M8): 내 친구 코드(복사·보내기), 친구 코드 넣기, 친구 목록(위치 공유 중 표시, 끊기는 한 번 더 확인). 서버 계정이 없으면 쓸 수 없다고 알린다
- 기본 화면 모드 (지도 / 미니멀 / 대시보드)
- 주행 지도 보기 (전체 코스 / 나를 가운데 / 진행 방향 위, 사용자 요청)
- 주행 중 바탕 지도: 보이기(기본) / 끄기(코스 선만) (사용자 요청)
- G미터 최대값: 1.5 / 2(기본) / 2.5 / 3 g (사용자 요청)
- 주행 지도에 친구 위치: 보이기(기본) / 끄기 (사용자 요청, 주행 준비에도 있음)
- 상단 표시 값 두 칸 (8.3.1)
- 델타 색 (초록·빨강 / 파랑·주황)
- 게이트 폭: 지도·GPX로 만드는 새 코스의 출발선·도착선 폭, 10~60 m(5 m씩, 기본 30 m). 자동 코스는 엔진 기본값 (M10)
- 거치 팁 (주행 준비와 같은 내용, 펼쳐 보기)
- 동기화 상태 (대기 건수, 마지막 오류, 다시 시도 버튼)
- 개발자 메뉴: 재생 모드 (10.2 참고), 센서 기록 테스트 (원본 파일 `.json.gz`/`.json` 내보내기, 실주행 테스트 데이터 수집용)

| 상황 | 처리 |
|---|---|
| 위치 권한 거부 | 주행 불가. 설정에서 켜는 방법을 플랫폼별로 안내 |
| 모션 권한 거부 | GPS만으로 기록. "정확도 낮음, G값 없음" 표시 |
| GPS 약함·잠깐 끊김 | 센서로 이어서 추정. 상태 표시 |
| GPS 5초 넘게 끊김 | 그 랩 무효, 델타를 "—"로 숨김. 회복되면 다음 게이트부터 정상 |
| 앱 중단 (전화, 화면 꺼짐, 강제 종료) | 5초 단위 저장, 화면이 가려지면 바로 저장. 다시 열면 "중단된 주행 이어서 하기 / 끝내기"를 물음. 중단 구간이 걸친 랩은 무효. 다른 창(같은 폰의 브라우저 탭과 설치한 앱)에서 기록 중인 세션은 중단으로 보지 않음 |
| 종료할 때 저장 실패 | 기록을 끝내지 않고 "다시 저장"을 보여줌. 저장하지 못한 기록은 앱을 닫기 전까지 메모리에 남음 |
| 화면 꺼짐 방지 미지원·실패 | 사용자에게 자동 잠금을 끄라고 안내 |
| 통신 없음 | 기록·델타는 폰에서 동작. 업로드는 대기열에 넣고 지수 백오프로 재시도 |
| 업로드 중복 | 폰에서 만든 id로 upsert해서 중복 방지 |
| 파일 게이트웨이·R2 오류 | 업로드 대기열에 남기고 재시도. 파일이 올라가기 전에는 표에 세션을 넣지 않음 |
| 서버 장애·통신 없음 | 기록과 델타는 폰에서 계속 동작하고 동기화만 대기. 첫 실행(계정 만들기)은 통신이 필요하므로 "서버에 연결할 수 없어요" 안내 후 다시 시도 |
| 거치 보정 실패 | "G 보정 안 됨" 표시. 직선 가속 때 자동으로 다시 시도 |
| 주행 중 거치 각도 변화 | 재보정 (7.2) |
| 랩/편도 판단이 애매함 | 주행 종료 때 사용자에게 물음 |
| 출발선 통과 실패 | 게이트 폭을 넉넉하게 기본 설정. 코스 상세에서 선 위치 수정 가능 |

## 10. 테스트

### 10.1 자동 테스트 (Vitest, GitHub Actions에서 통과해야 배포)

**가상 주행 생성기 (`test/generators/`)**
- 정답 궤적을 만든다: 타원 서킷, 직선이 있는 오벌 서킷, 헤어핀이 있는 와인딩 편도, 코스가 가까이 붙은 구간.
- 1Hz GPS를 만든다: 3~5m 가우시안 잡음, 가끔 튀는 점, 3초와 8초 끊김.
- 50Hz 모션을 만든다: 잡음, 바이어스, 임의의 거치 각도.

**검증 항목**
- 랩타임 오차: 가상 데이터 기준 RMS 0.1초 이하 (초기값, `config.ts`에서 조정). 최대값이 아니라 RMS로 본다(M4 결정: 1Hz GPS 잡음 때문에 최대값 0.1초는 맞출 수 없다).
  - 편도는 게이트를 느리게 지나면 오차가 커진다(정지 출발 20m 지점: RMS 약 0.19초). 자동 편도 게이트를 20m 안쪽에 두는 이유 중 하나다.
- 델타 오차: RMS 0.15초 이하, 구간 기록
- 게이트 통과 시각
- 헤어핀과 근접 구간에서 s가 튀지 않는지
- 거치 보정이 복원한 각도의 오차
- 무효 랩 판정 (끊김, 이탈, 거리 불일치)
- GPX 왕복: 내보낸 뒤 다시 불러오면 같은 결과가 나오는지
- CSV 내보내기: 열 순서와 이름, 단위, `utc_time`이 단조 증가하는지, 비교 랩이 없을 때 `delta_s`가 빈칸인지
- 고스트 위치: 가상 데이터에서 고스트의 코스 거리가 비교 랩의 실제 위치와 맞는지
- 시간 정보 있는 GPX와 없는 GPX
- 가민 확장 속도값 읽기

**파일 게이트웨이 테스트** (Cloudflare의 Workers용 Vitest 환경 `@cloudflare/vitest-plugin`, `worker/` 폴더의 별도 패키지)
- 토큰 없음 → 401, 다른 사용자 폴더 → 403, 잘못된 경로 → 400, 크기 초과 → 413
- 정상 업로드 뒤 `HEAD`와 `GET` 결과가 올린 파일과 같은지
- 허용하지 않은 출처(Origin)의 요청이 CORS에서 막히는지

**실주행 회귀 테스트**
- 실제 주행 기록이 생기면 `test/fixtures/`에 추가해서 회귀 테스트로 쓴다.

### 10.2 재생 모드
- 저장된 세션, GPX, 가상 데이터를 주행 화면에 실제 속도나 배속으로 흘려보낸다.
- 운전하지 않고 책상에서 화면과 델타를 확인할 수 있다.
- 재생 중 지도 모드는 운전 중이 아니므로 OpenStreetMap 지도(어둡게) 위에 코스·고스트·내 위치를 그린다. 주행과 같은 왼쪽 위 나침반 버튼으로 "전체 코스"(코스가 화면을 꽉 채우게, 여백 20 px), "나를 가운데"(확대 17단계로 따라감), "진행 방향 위"(지도판을 돌려 내비처럼)를 바꾼다. 보기는 설정의 주행 지도 보기와 같다. 지도 조작(끌기·확대)은 두 번 탭과 겹치지 않게 끈다. 지도를 불러오지 못하거나 통신이 없으면 타일 없이 그린다 (사용자 요청, M9)

- **가상 친구 따라가기 (사용자 요청 "앞 친구 델타를 직접 시뮬로 돌려보기"):** 설정 → 재생 모드 → "가상 친구 따라가기". 오벌 서킷에서 앞 친구 "지훈(가상)"이 달리고 나는 뒤따른다. 목표 간격 2.0초로 간격이 2.7초(멂 +0.7) → 2.0초(유지) → 1.4초(가까움 −0.6)로 바뀌고 66초에 친구 위치가 끊긴다. 실제 폰처럼 친구 위치는 1초마다(GPS 잡음 3 m, GPS 속도 포함) 0.8초 늦게 들어오고 내 GPS도 0.5초 늦다 (`sim/friendScenario.ts`). 주행 화면은 실제 앞 친구와 똑같이 계산한다(델타 칸 "Delta (지훈(가상))", 지도의 친구 아이콘 예측). 이때만 재생 중에도 앞 친구 간격을 쓴다. 신호 끊김은 내 위치의 GPS 기준 시각으로 판단한다(폰 시계와 무관).

### 10.3 실차 테스트 순서
1. 아이폰과 안드로이드 각각: 권한, 화면 꺼짐 방지, 홈 화면 설치, 5초 단위 저장 확인
2. 짧은 저속 루프 코스: 첫 주행 자동 코스 생성, 랩 감지, 두 번째 주행 델타 확인
3. 비행기 모드로 주행한 뒤 통신을 켜서 자동 업로드 확인
4. 서킷: 공식 계측(트랜스폰더) 기록과 앱 랩타임 비교. 1차 목표 오차는 ±0.3초 이내
5. 아이폰 기록과 안드로이드 기록을 서로 고스트로 비교했을 때 G값 부호와 크기가 맞는지 확인
6. 1주일 넘게 앱을 안 쓴 뒤에도 업로드가 되는지 확인

### 10.4 인수 기준
- 1장의 성공 기준 6가지를 모두 만족하면 1단계 완료로 본다.

## 11. 설정·배포 절차 (사용자는 브라우저로만)

1. **GitHub:** 저장소를 만들고, Settings → Pages에서 소스를 "GitHub Actions"로 지정한다.
2. **Cloudflare:**
   - 계정을 만들고 R2를 켠다. 무료 한도 안에서는 과금이 없지만, 켤 때 결제 수단 등록을 요구할 수 있다.
   - Workers & Pages에서 workers.dev 하위 주소를 정한다.
   - API 토큰을 만든다 (Workers 스크립트·D1·R2 편집 권한). 계정 ID를 확인한다.
   - R2 버킷과 D1 데이터베이스, 표는 배포 때 자동으로 만든다.
3. **GitHub Actions 비밀 등록:** `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`. 배포 첫 단계가 값을 다듬는다: 같이 붙여 넣은 공백·줄바꿈·`Bearer`·토큰 확인용 curl 명령은 떼고 토큰만 꺼내며, 계정 ID가 틀리면 토큰으로 접근할 수 있는 계정(하나일 때)을 쓴다. 토큰이 살아 있는지·Workers 권한이 있는지 Cloudflare에 미리 묻고 문제를 쉬운 말로 알린다 (M6 결정)
4. **첫 배포:** main에 푸시하거나 Actions 탭에서 "테스트·배포"를 실행하면 자동 테스트 → 서버 배포 → 서버 응답 확인(열쇠 없이 401, 앱 주소 사전 요청 204, 다른 주소 403. 데이터는 만들지 않음) → 웹앱 배포(서버 주소 자동 반영)가 진행된다.
5. 폰에서 링크를 열고 홈 화면에 추가한다.

**참고**
- 익명 계정 만들기 남용 방지: 같은 IP에서 1시간에 10개까지. 필요하면 2단계 이후 캡차를 추가한다.
- 2단계 대비: 정식 로그인(구글·카카오)은 Worker에 붙이고, 익명 계정의 user id를 그대로 이어 간다.
- 서버 데이터는 Cloudflare 대시보드의 D1 → gachitayo → Console에서 볼 수 있다.

## 12. 알려진 제약

- 웹앱은 화면이 켜져 있고 앱이 앞에 떠 있을 때만 기록된다. 거치하고 화면을 켠 채로 쓰는 것이 전제다.
- 위치 공유도 앱이 화면에 보일 때만 보낸다. 특히 아이폰은 앱을 내리면 멈춘다 (13.3 Expo 전환 뒤 나아진다). 친구에게는 5초마다, 최대 2분 전 위치가 보인다.
- 위치 공유는 D1 쓰기를 쓴다: 한 사람이 1시간 공유하면 약 720행. 10명이 하루 3시간씩이면 무료 한도(하루 10만 행)의 약 20%다.
- 폰 GPS는 1초에 1번 정도라 정확도 목표(±0.3초)는 실측으로 확인해야 한다.
- 익명 계정은 로그아웃, 브라우저 데이터 삭제, 기기 변경 시 다시 접근할 수 없다.
  - 서버 데이터는 남지만 그 계정으로는 들어갈 수 없다.
  - 그래서 1단계에는 로그아웃 버튼이 없고, 홈 화면 설치와 빠른 업로드를 권장한다.
- 아이폰 사파리 탭으로 쓰면 오랫동안 안 쓴 사이트의 저장 데이터가 지워질 수 있다. 홈 화면 설치를 권장한다.
- OSM 타일은 소규모 데모용이다. 사용자가 늘면 타일 제공자를 바꿔야 한다.
- 공도 주행: 앱은 안전 안내만 한다. 여러 명이 함께 달리는 실시간 기능(3단계)은 서킷 전용으로 설계한다. 앞 친구 한 명과의 간격(M9)은 사용자 결정으로 어디서나 쓰되, 목표 간격은 1초 이상만, 처음 켤 때 안전 안내를 한다.
- 앞 친구 간격의 실시간 전달은 Cloudflare Durable Objects(사람마다 방 하나, 위치는 저장하지 않음)를 쓴다. 무료 플랜은 하루 10만 요청까지이고, WebSocket 메시지가 이 한도에 어떻게 세어지는지는 실제로 쓰며 확인한다. 앞 친구는 1초에 한 번쯤(GPS 받을 때마다) 보낸다.
- 간격 정확도는 두 폰의 GPS 잡음과 시계 차이에 달려 있다. 가상 데이터에서 0.2초 안(느린 헤어핀은 0.5초 안팎). 실차에서 확인한다.
- 무료 한도: D1 저장 5GB·하루 쓰기 10만 행·읽기 500만 행, R2 저장 10GB, Worker 하루 10만 요청. 20분 주행 한 번의 파일은 약 1~2MB로 추정한다 (실측 후 갱신).

## 13. 1단계 이후 추가 기능

각 항목의 "1단계에서 남겨둘 확장 지점"만 1단계에 반영한다. 기능 자체는 1단계가 끝난 뒤 사용자 확인을 받고 시작한다.

**순서 (사용자 결정 "가", 2026-11-12):** 웹앱으로 짧게 실차 측정 → 13.3 Expo 전환 (13.2 OBD 함께) → 13.1 영상에 입히기. 장 번호는 처음 적은 순서 그대로 둔다.

### 13.1 영상에 입히기 (폰 안에서) — Expo 전환 뒤

**목표:** 고프로, 오즈모 액션, 폰으로 찍은 영상에 같이타요 주행 데이터를 겹쳐서 폰 안에서 새 영상으로 저장·공유한다.

**흐름**
1. 분석 화면 → "영상에 입히기" → 세션 고르기 → 폰 앨범에서 영상 고르기 (MP4/MOV, H.264/H.265). 고프로·오즈모 영상은 각 제조사 앱으로 폰에 옮긴 것을 쓴다.
2. 싱크 맞추기 (아래)
3. 미리보기: 영상을 재생하면서 위에 오버레이를 실시간으로 겹쳐 보여준다 (인코딩 없음).
4. 오버레이 고르기: 델타, 속도, G미터, 미니맵(코스 선 + 현재 위치), 랩·랩타임, 구간. 배치는 프리셋 몇 가지 중에서 고른다.
5. 범위 고르기: 기본은 고른 랩 1~2개 + 앞뒤 5초
6. 영상 만들기: 진행률 표시, 취소 가능. 끝나면 앨범 저장 또는 공유

**싱크 방법 (위에서부터 시도)**
1. **고프로 자동:** 영상 안의 GPS 데이터(GPMF의 GPS 시각)를 읽어 `utc_time`(6.9)과 맞춘다.
2. **파일 시각으로 대략:** 영상 메타데이터의 촬영 시각으로 초 단위까지 먼저 맞춘다.
3. **수동 기준점:** 사용자가 영상 슬라이더로 출발선을 지나는 장면을 찾아 "여기가 출발선"을 누르면, 그 프레임을 데이터의 출발선 통과 시각에 맞춘다. ±1프레임 미세 조정 버튼을 둔다.
4. **두 기준점(선택):** 영상 끝쪽에서 한 번 더 지정하면 카메라 시계가 조금씩 벌어지는 것까지 보정한다.
- 오즈모 액션의 GPS 데이터를 자동으로 읽는 것은 형식을 조사한 뒤 추가한다. 그 전에는 2·3번 방법을 쓴다.
- 목표 정확도: 1~2프레임 이내

**렌더링 (웹앱 기준)**
- 브라우저 WebCodecs로 디코드 → 캔버스에 "오버레이 그리기"(5.1의 12번)로 합성 → H.264로 인코드 → 순수 JS MP4 먹서로 파일 생성. Web Worker에서 처리한다.
- 오디오는 가능하면 재인코딩 없이 원본을 복사한다.
- 출력 기본값: 1080p, 원본 fps
- 렌더링 중 화면 켜짐 유지. 렌더링하지 못하는 브라우저면 미리보기만 제공하고 CSV 내보내기(6.9)를 안내한다.
- 4K 장시간 영상은 오래 걸리고 발열이 크므로 범위를 짧게 하도록 기본값을 둔다.

**1단계에서 남겨둘 확장 지점**
- 처리된 궤적 파일과 CSV에 GPS 기준 절대 UTC 시각(`utc_time`)이 있어야 한다 (6.7, 6.9).
- 델타·속도·G·미니맵 표시는 "시각 t의 상태 → 캔버스 그리기" 함수(`ui/overlay/`)로 만들고, 지도 모드 주행 화면이 이것을 쓴다. 13.1은 같은 함수를 영상 프레임 위에 호출한다.

### 13.2 OBD 연동 — Expo 전환(13.3)과 함께

**어댑터 기준**
- 차 쪽: OBD-II 표준 (국내 2010년 이후 차량 대부분). 차마다 지원 항목이 다르므로 연결 직후 지원 항목(Mode 01, PID 00/20/40)을 물어보고 있는 값만 쓴다. 전기차는 표준 항목이 거의 없을 수 있다.
- 어댑터: **ELM327 명령 호환 + BLE(블루투스 저전력)**만 지원한다. 예전식 블루투스와 와이파이 어댑터는 대상에서 뺀다.
- 기준 테스트 기기: OBDLink CX 1개 + 저가 BLE ELM327 호환품 1개. 인포카 단말기는 제조사에 ELM327 표준·BLE·타 앱 연결 지원을 확인한 뒤에 목록에 넣는다.
- BLE 어댑터는 보통 한 번에 앱 하나만 연결된다. 다른 OBD 앱과 동시에 쓸 수 없다는 안내를 넣는다.

**기본 항목:** RPM(0C), 차속(0D), 스로틀(11), 엔진 부하(04), 냉각수 온도(05), 흡기 온도(0F)

**시간 동기화 (목표 ±50ms)**
1. 모든 OBD 값에 폰의 단조 시계로 시각을 찍는다. 기준은 요청 시각과 응답 시각의 중간이다.
2. OBD 차속과 GPS 속도·가속도 센서를 가속·감속 구간에서 겹쳐 보고, 가장 잘 맞는 시간 차이로 지연을 추정해 보정한다. 계기 속도와 GPS 속도의 배율 차이도 함께 추정한다.
3. 주행 후 전체 기록으로 다시 정렬한다.

**화면:** 주행 준비에 "OBD 연결"(한 번 연결하면 다음부터 자동), 상단 표시 값 목록에 RPM·스로틀·냉각수 온도, 분석에 RPM·스로틀 그래프, CSV에 열 추가

**1단계에서 남겨둘 확장 지점**
- 원본 파일과 내부 데이터 구조가 센서 채널을 추가할 수 있어야 한다 (예: `channels: { obd_rpm: { t: [], v: [] } }`).
- CSV 열은 고정 열 뒤에 채널 열을 덧붙일 수 있게 만든다.

### 13.3 Expo(React Native) 앱 전환

**이유:** 내비를 켜도 이어지는 백그라운드 기록, 아이폰 OBD 연결, 앱이 직접 영상을 녹화해서 싱크가 필요 없는 촬영

**재사용:** `engine/*`, `normalize/`, `gpx/`, `export/`, 데이터 형식, 서버(Worker·D1·R2)

**교체:** 센서 수집(expo-location 백그라운드 작업, expo-sensors), 폰 저장소(SQLite), 화면(React Native), 지도·차트 라이브러리, 빌드·배포(Expo 클라우드 빌드를 GitHub Actions로 실행, 아이폰은 TestFlight. 애플 개발자 계정 연 99달러)

**주의:** 위치 권한을 "항상 허용"으로 받아야 할 수 있다. 백그라운드에서 1초에 50번 받는 모션 센서가 유지되는지는 실기기로 확인한다.

**1단계에서 남겨둘 확장 지점:** 5.1 규칙 그대로. 계산 엔진은 브라우저 API를 직접 쓰지 않는다.

### 13.5 코스 별점·후기와 코스 공유 — 앱 전환(13.3) 뒤 (마스터플랜)

사용자 결정 (2026-11-12): 지금은 기본 코스만 목록에 넣는다. 서버로 올리기·별점·공유는 앱으로 넘어갔을 때 만든다.

- **별점·후기:**
  - 별 1~5개와 한 줄 후기(60자 이내).
  - 그 코스를 달려 본 사람만 남길 수 있다. 그 코스에서 유효 랩(편도는 완주)이 하나 이상 있어야 한다.
  - 코스 목록에 평균 별점과 개수를 보인다. 코스 상세에서 후기 목록을 보고, 내 별점·후기를 남기거나 고치거나 지운다.
- **사용자 코스 공유:** 사용자가 자기 코스를 올려 모두의 목록에 넣는다. 별점·후기는 기본 코스와 같은 방식이다.
- **서버 설계 메모 (그때 확정):**
  - 공유 코스는 모두가 같은 번호를 쓴다. 지금 `courses` 표는 사람마다 자기 행이라, 공유 코스는 따로 둔다. 예: 시스템 소유 행, 또는 별도 `shared_courses` 표.
  - 이 폰의 사본은 `builtin` 키(또는 공유 코스 번호)로 공유 코스와 잇는다.
  - 후기 표: 예: `course_reviews(course_id, user_id, stars, comment, created_at, updated_at)`, 사람당 코스마다 하나.
  - 달려 본 사람인지는 서버에 올라온 내 유효 랩으로 확인한다.
  - 신고·숨기기 같은 관리 기능도 그때 정한다.
