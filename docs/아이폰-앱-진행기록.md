메리고(chungyakgo-maker/marrygo)에서 2026-11-13~16에 한 방식을 따른다. 다른 점은 아래 "메리고와 다른 점"에 적는다.

| | |
|---|---|
| 앱스토어 이름 | 디고: 드라이브 코스 추천 |
| 홈 화면 이름 | 디고 |

## 메리고와 다른 점

- 사이트 = GitHub Pages(React, Vite), 서버 = Cloudflare Worker + D1 + R2. Supabase 를 쓰지 않는다 → SQL 붙여 넣을 일이 없다(표는 배포 때 자동).
- 앱인지 알아보기: 사용자 에이전트가 아니라 앱으로 빌드할 때 정해진다(`vite build --mode app`, `isApp()`). 미리 그린 HTML 이 없어 CSS 클래스로 숨길 필요가 없다.
- 아이폰 기능은 앱 빌드에 들어간 Capacitor 부품으로 부른다(사이트에 넣는 방식이라 가능). 사람이 고르지 않는 부름에는 기다림 한도 5초(`nativeCall`, 메리고에서 막혔던 2번).
- 애플 로그인·카카오 로그인 돌아오기·탈퇴 때 애플 해지는 Worker 가 한다(Supabase 대신). 애플 로그인 키(.p8)는 GitHub 비밀값 → 배포 때 자동으로 Worker 비밀값(메리고에서 막혔던 4번 해당 없음).
- 광고 없음.
- 커뮤니티: 글·사진 게시가 없고 친구·그룹 방에서 닉네임만 보인다. 심사에서 물으면 그룹 방 "내보내기"를 더한다.

## 1단계: 껍데기 + 로그인 코드 (2026-11-17, 작업 갈래 app-login, 배포 전)

이미 되어 있던 것(ios 갈래, 2026-11-13~16): Capacitor 8 껍데기(Swift 패키지), 화면이 꺼져도 위치 기록, 화면 꺼짐 방지, 공유·파일 저장, 내비 앱 열기, 계정 삭제, 약관 페이지, SceneDelegate 에서 내 화면 클래스 쓰기(메리고 1번).

이번에 한 것:
- 애플 로그인(Swift 플러그인 DgoAuth, App.entitlements) + 앱용 카카오 로그인 창(ASWebAuthenticationSession) + 탈퇴 때 애플 해지 + 로그인 연결(설계 docs/superpowers/specs/2026-11-17-app-login-design.md)
- 로그인 단추: 앱은 "로그인" 하나 → [카카오로 로그인] [Apple로 로그인] 고르는 창(메리고와 같게). 웹은 카카오 단추 그대로
- 번들 ID kr.dgo.app, 새 아이콘·시작 화면, 아이폰 전용(TARGETED_DEVICE_FAMILY 1), arm64, PrivacyInfo.xcprivacy(메리고와 같게)
- codemagic.yaml (메리고와 같게, 다른 점: 웹앱을 앱용으로 만드는 단계, 프로젝트 경로 ios/App)
- GitHub 맥 업로드 작업(testflight.yml)은 뺐다. 시뮬레이터 빌드 확인(ios.yml)은 남김(공개 저장소라 무료)
- 약관: 연락처·시행일, 애플·카카오 로그인 문장
- 앱스토어 자료 docs/release/app-store.md (이름·번들 ID·영어 심사 메모)

남은 것: 서버에 애플 로그인 올리기(배포, 세영 허락 뒤), 세영의 애플·Codemagic 설정, Codemagic 첫 빌드 → TestFlight 확인.

## 2단계: 서명·서버 준비 (2026-11-17, 세영 설정 + 서버 배포)

- 서버: 애플 로그인·카카오 앱 돌아오기·탈퇴 때 애플 해지를 main 에 올림(7c06e89, 세영 허락). 확인: `/auth/providers` → `{kakao:true, apple:true}`, `/auth/apple` 빈 요청 400, 앱 출처(`capacitor://localhost`) 사전 요청 204, D1 0010(apple_tokens·apple_seen) 적용.
- 세영 설정(애플 개발자 사이트):
  - App ID `DGO`(kr.dgo.app)에 Sign In with Apple 켬
  - 애플 로그인 키 `DGO Sign in with Apple`(Primary App ID = DGO). .p8 은 세영이 보관(한 번만 받을 수 있음)
  - App Store 배포 프로필 `DGO App Store`(메리고 배포 인증서 marrygo_dist — **2027-11-16 만료**, 메리고와 같이 갱신)
  - App Store Connect 새 앱 "디고: 드라이브 코스 추천"(한국어, SKU dgo-ios)
- 세영 설정(Codemagic, 메리고와 같은 개인 계정): GitHub 앱 허락에 gachitayo 추가(marrygo 그대로) → 앱 추가, Code signing identities → iOS provisioning profiles 에 `dgo_appstore`(DGO App Store, kr.dgo.app) 받음. API 키는 메리고 것 `marrygo`.
- 세영 설정(GitHub 비밀값): `APPLE_SIGNIN_KEY_P8`·`APPLE_SIGNIN_KEY_ID`·`APPLE_TEAM_ID` → main 같은 버전 다시 실행(세영 허락)으로 Worker 비밀값에 들어감(배포 기록 "Worker 비밀값: … APPLE_SIGNIN_KEY_P8, APPLE_SIGNIN_KEY_ID, APPLE_TEAM_ID" 확인). 이제 탈퇴 때 애플 해지까지 된다.
- TestFlight 앱 설치(세영 아이폰).

다음: Codemagic 첫 빌드(갈래 app-login, 작업 "디고 아이폰 → TestFlight") → App Store Connect 처리 → TestFlight 내부 테스트 → 세영 아이폰 확인.

## 3단계: 첫 빌드 → TestFlight + 첫 실차 고침 (2026-11-17)

- Codemagic 첫 빌드(빌드 1)는 프로필이 저장되지 않아 "No matching profiles" → 세영이 Fetch profiles 를 다시 해 `dgo_appstore` 저장 → 빌드 2 성공(2분 55초, App Store Connect 로 올라감).
- TestFlight: 내부 테스트 그룹(세영 본인) 설치 완료. 외부 테스트 그룹 "무브먼트"(공개 링크, 최대 10명) 만들고 베타 심사 제출(심사 대기).
- 실차 사용자 요청 고침(갈래 app-login, 시안 승인 뒤):
  - 목적지 주행: 지나온 경로 선 지우기(경로 진행 거리를 지도에 넘김, 이탈 중 유지, 새 경로면 처음부터)
  - 내 차 표시 약 2배 + 설정 "내 차 표시 (주행 지도)": 화살표(기본)·흰 차·파란 점·빨간 차
- 다음: 세영이 Codemagic 빌드 → TestFlight 새 빌드 확인. 웹 사이트 반영(main 배포)은 세영에게 따로 묻는다.
- 2026-11-18 실차 사용자 요청 고침(A·B 둘 다, 갈래 app-login): 주행 지도 두 손가락 확대·축소를 손가락 따라 부드럽게(계단 없이), + / − 는 스르륵, 두 손가락 비틀어 지도 돌리기(돌린 방향 유지, 나침반 누르면 다시 진행 방향 위). 원인: 처음부터 확대는 한 번에 한 단계(2배)씩, 지도는 손으로 못 움직이게 만들었었음(고장 아님).
- 앱 업데이트 방식(세영 질문): 디고는 웹 화면을 앱 안에 넣어서, 앱 화면을 고치면 Codemagic 빌드가 다시 필요(웹 배포로는 앱이 안 바뀜). 서버(Worker) 변경은 바로 반영. 정식 출시 뒤에는 업데이트마다 App Store 심사. "라이브 업데이트"는 정식 출시 전에 할지 정하기로.
- 2026-11-18 웹 배포 1차(세영 "웹먼저 배포해봐", main 79cc660 = app-login 062a6b5): 지나온 경로 지우기·내 차 표시 4가지·부드러운 확대/돌리기·새 로고. 서버 그대로. 배포 확인(서버 주소·로그인 선택지·웹 출처) 통과.
- 2026-11-18 이어서(app-login, 웹 배포 전): 상단 표시 값 주행 거리·평균 속도, 지도 손 동작 메인·주행 똑같이(끌기·비틀기·"내 위치로"·주행 3초 뒤 저절로 돌아오기). 새 로고는 아이폰 앱 아이콘·시작 화면에도 들어감 → 다음 Codemagic 빌드부터.
- 2026-11-18 웹 배포 2차(세영 "웹은 2차배포해 앱은 아직 대기", main 86cb3ed = app-login de024d6): 주행 거리·평균 속도, 지도 손 동작 메인·주행 똑같이. 서버 그대로. 배포 확인 통과. 아이폰 빌드는 세영이 웹 확인 뒤에.
- 2026-11-18 세영 지적 "주행 중엔 여전히 메인 지도랑 동작이 다르다" → 주행 선 지도도 메인 지도와 같은 지도 프로그램이 손 동작을 직접 받게 고침(app-login, 웹 배포 전). 실제 지도로 브라우저에서 끌기·손가락 기준 확대·3초 뒤 돌아오기 확인.
- 2026-11-18 웹 배포 3차(세영 "ㅇㅇ 배포해", main fee8a3f = app-login 57229d3): 주행 지도 손 동작을 메인 지도와 같게. 서버 그대로. 배포 확인 통과. 아이폰 빌드는 계속 대기.
- 2026-11-18 카톡 공유 미리보기가 예전 그대로(세영): 원인 = 웹 페이지에 미리보기 정보(og)가 없고 카카오가 예전 미리보기를 저장해 둠. 웹 이름도 디고로(결정 (나)), 미리보기 정보·그림 추가 → 웹 배포 후 카카오 공유 디버거에서 저장된 미리보기 초기화. 아이폰 앱은 다시 빌드할 필요 없음(카톡이 웹 페이지를 읽음).
- 2026-11-18 웹 배포 4차(main 2ce0f65 = app-login a08318e): 웹 이름 디고 + 링크 미리보기. 서버 그대로. 배포 확인 통과. 남은 것: 세영이 카카오 공유 디버거에서 https://chungyakgo-maker.github.io/gachitayo/ 미리보기 초기화.
- 2026-11-18 아이폰 앱 실행 애니메이션(세영 "여기 이걸로 앱실행애니메이션 초기 로딩에 넣어" → "아이폰 앱만 넣어", 갈래 app-login, 배포 아님): 확정 시안 DgoSplash 2초, 끝나면 메인 화면. 아이폰 고정 시작 화면은 같은 파란색 한 장으로. 웹은 그대로. 다음 Codemagic 빌드부터 보인다.
- 2026-11-18 팀·팀 주행·프로필 사진(세영 "팀 만들기 최대 15명, 친구를 넣어 … 팀은 최대 5개", "프사 동그랗게, 업로드 방식으로만", 시안 승인 뒤, 갈래 app-login, 배포 전): 서버(D1 0011 teams·team_members·users.avatar, R2 avatars/, /api/teams…, /avatar/{id}.jpg)와 앱 화면. 아이폰은 사진 고르기에 카메라·사진 보관함 문구를 더했다. 서버 배포(main)는 세영에게 묻는다 — 서버가 먼저 올라가야 새 화면이 동작한다.
- 2026-11-18 검토(새 검토자) 지적 고침: 팀에서 빠짐·나감·팀 지움·탈퇴 때 팀 주행 방에서도 빠짐/닫힘, 닫힌 주행 다시 열기 409, 방장 순서 유지, 합치기 때 팀·프사, 코드 방엔 프사 안 실음, 편집 화면 새로 받기, 긴 한글 이름 링크 등. 로컬 실제 서버+앱으로 두 사람 전체 흐름 확인.
- 2026-11-18 서버 배포(세영 "서버 올리고 정상동작해야해", 웹 화면은 그대로 — 결정 "웹은 그냥 둬라"): main 951bd77 = 지금 웹 + app-login 89bb1ae 서버. D1 0011 적용, 비밀값 그대로, 서버 주소 확인. 실제 서버에서 임시 계정 둘로 친구·사진·팀·팀 주행·빼기·지우기·예전 방 코드까지 확인 후 두 계정 지움. 다음: Codemagic app-login 빌드 → 아이폰에서 팀 확인.

## 정식 버전 구상 (2026-11-18, 세영 결정 — 아직 진행 안 함, 정식 출시 준비 때 시안부터)

- 이유: 위치기반서비스사업 신고 전이라 정식 버전은 **서로 위치 공유를 끄고**, 사업자등록·신고 뒤 다시 켠다. 테스트 버전(TestFlight)은 지금 그대로(위치 공유 켬).
- 방법: 빌드 때 정하는 스위치 하나(위치 공유 켬/끔). Codemagic 작업을 테스트용(켬)·정식용(끔) 둘로. 서버에서 원격으로 켜지 않는다(심사 뒤 숨긴 기능을 켜면 애플 2.3.1 위반).
- 빠짐(단추는 숨김 — "업데이트 예정" 창은 애플 2.1 미완성 거절 위험이라 세영 "추천대로"): 팀 방 주행 지도의 다른 차, 팀 방 앞 차 간격, 메인 지도 친구 위치, 주행 준비 "주행 중 위치 공유", 상단 칸 앞 친구 간격.
- 남음: 팀 방(만들기·초대·순서·방장 목적지 같이 받기), 방장 차 간격은 방 화면 안내 문구로만, 목적지 길찾기·표지판, 친구 목록·맺기, 기록(서버 올리기 포함)·분석 등 나머지 전부.
- 웹도 같이 숨김(세영: 웹은 비공개해도 되지만 숨김). 약관·개인정보·앱스토어 정보에서 위치 공유 문장을 빼고, 다시 켤 때 되돌린다.
- 남은 확인: 기록 서버 올리기·목적지 길찾기도 위치가 서버로 간다 → 세영이 위치정보지원센터에 문의할 때 같이 묻기.

## 기울기 웹 시험 (2026-11-19, 세영 "기울기가 부정확해 웹에서 테스트하게 앱은 건들지말고 … 0에서도 기울기 동작하게끔해" → "ㅇㅋ 진행해", 갈래 app-login)

- 1.0.1 심사용 앱 코드는 `release-1.0.1` 갈래에 그대로 남김 (1.0.1 을 다시 빌드할 일이 있으면 Codemagic 에서 그 갈래로)
- **웹 빌드에서만** 기울기 = 센서 기울기(폰이 0점에서 기운 각도, 정차·저속에서도) + 계산 기울기(속도 × 도는 빠르기, 자이로를 믿을 수 있으면 자이로 — GPS 방향보다 덜 늦음). `src/engine/derive/leanFusion.ts`, 스위치 `features.ts` leanFused() = 앱이 아니면 켬. 앱은 예전 계산(`lean.ts`, 시속 15km 미만 0) 그대로
- 0점: 주행 준비(바이크) "기울기 0점" 카드의 "0점 맞추기"(바이크를 똑바로 세우고) > 시속 20km 넘게 곧게 5초 달리면 자동 > 정차 때 위 방향
- 설정 › 개발자 메뉴 › **기울기 시험**(`#/dev/lean`): 센서 기울기·계산 기울기·최종·속도를 나란히. "시험 시작"이 주행 준비를 열고(기록은 끝내면 지움) 그 상태로 달려도 값이 움직인다
- 시험으로 확인: 차(기울지 않음)로 코너를 돌면 예전 계산은 40°까지 눕지만 합친 값은 거의 0 (95% 가 6° 안). 주행 요약의 최대 기울기는 아직 예전 계산(처리된 궤적)
- **기울기 시험 화면 바늘 그림 (2026-11-19, 세영 "센서기울기가 시각적으로 보기에 좋을거같다" → 시안 → "좋아 넣어서 배포해")**: 센서 기울기·최종 기울기를 주행 화면과 같은 반원 바늘 칸으로 크게, 시험 동안 왼쪽·오른쪽 최대(0점을 맞추면 처음부터). 계산 기울기·속도·0점은 글자
- **정식 앱에도 켬 (2026-11-19, 세영 "이대로 정식버전(위치공유 x)도 배포해")**: `features.ts` leanFused() = 늘 켬 (빌드 값 `VITE_LEAN_FUSED=off` 로만 끔). 아이폰 정식·테스트 빌드 모두 새 기울기 + 주행 준비 "기울기 0점" 카드. 재생·모의주행은 예전 계산 그대로(심사 메모의 "모의주행으로 기울기 보기"가 그대로 됨). 심사 메모·앱스토어 설명의 기울기 문장 고침
